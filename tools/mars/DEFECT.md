# Дефект ядра МАРС при длине области > 1024 зон

Research-only. Репозиторий и образы дисков не изменялись.

## Найденное место

Команда 10 (`MКСТL`, `re-mars.asm:1474-1517`, листинг `re-mars.txt:1680-1728`):

- `03437-03440`: `СЧ DBDESC; СДА 64+18; ЗП DBLEN` - длина области из дескриптора.
- `03441` (asm 1478): `УИ М5` - индексный регистр M5 получает значение DBLEN.
- `03447` (asm 1490): `СЛИА -1(М5)` - декремент M5 перед первой записью.
- `03450` (asm 1493): `do ЗП,(М5),bdbuf` -> `МОД BDBUF-BDVECT(M13); ЗП (М5)` - запись в `BDBUF[M5]`.
- `pasbdi.asm:10`: `P/BDBUF:,PC,1024` - буфер ровно на 1024 слова.

Следовательно, первая запись идёт по индексу `DBLEN-1`. При `DBLEN=1024` это 1023 (последний элемент буфера), при `DBLEN=1025` - 1024, то есть одно слово за границей `P/BDBUF`. Дальнейшие итерации пишут всё дальше за границей. Это единственное место команды 10, где счётчик зон используется как индекс в буфере фиксированного размера, и оно точно объясняет порог 1024/1025 и одну лишнюю запись дескриптора в трассе (`05454: *70 4037`, 1040 против 1041 события).

Следующий по коду вызов `PR1022` (`03463`, asm 1511) получает `MULEN = DBLEN` (`03464-03465`, asm 1512-1513). Дополнительные ограничения: `E10П1 = 1777₈` (asm 1580, маска 10 бит) в `PR1022` (asm 1086) и `lenmsk = 1777000000₈` (`re-bandit.asm:1006`) - но поле длины команды обмена MARS (`D01566`, asm 1596) имеет 15 бит, поэтому 1750 в него влезает. Эти ограничения вторичны по отношению к переполнению BDBUF.

## Патч

Файл `re-mars.asm` в этом каталоге - рабочая копия с минимальным патчем; `re-mars-limit-1024.patch` - unified diff.

Вставка после `ЗП DBLEN` (до инициализации M5 и до цикла записи):

    * буфер BDBUF на 1024 слова: длиннее - запись вне буфера
           СЧ    DВLEN
           НТЖ   Е11
           ПО    ОVЕRFL

- `СЧ DBLEN` - взять только что сохранённую длину (аккумулятор ниже всё равно перезагружается командой `СЧ DBDESC`).
- `НТЖ Е11`, где `E11 = 02000₈ = 1024` (asm 1583, листинг `03551`), сравнивает длину с ёмкостью буфера.
- `ПО ОVЕRFL` - при `DBLEN > 1024` передаёт управление существующему обработчику `OVERFL` (asm 777, листинг `02570`): `УИА 6(М16); ПБ ERR`, то есть диагностика 06 `ПЕРЕПОЛНЕНА` (`errors.md:8`).

Патч не меняет ни одной другой микрокоманды: затронут только путь команды 10 (а значит `NEWD` из `README.md`). Константы и обработчик уже существуют, новых символов и зависимостей нет.

Альтернатива с clamp (`ПО clamp; ...; СЧ E11; ЗП DBLEN`) не рекомендуется: дескриптор по-прежнему обещает 1750 зон, а физически будет создано 1024, что даёт рассогласование каталога и диагностику 05.
