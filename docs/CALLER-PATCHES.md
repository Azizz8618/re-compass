# Правки верхних слоёв для нового COMTUP

Сводка по исходникам архива Ильина. Все пути относительны к scratch-каталогу распаковки `/tmp/.private/azizz/opencode/ilyin-floppies/`.

## Ключевое отличие сигнатур

В `src/comtup.pas:139-166` обёртки объявлены с **двумя** параметрами:

```pascal
(*=e+*)procedure TPCMP1I(var p: integer; k: integer);
(*=e+*)procedure TPCMP1A(var p: alfa;    k: integer);
(*=e+*)procedure TPCMP1B(var p: boolean; k: integer);
(*=e+*)procedure TPCMP1P(var p: AnyPtr;  k: integer);
```

Все вызовы в верхних слоях имеют один аргумент `TPCMPAD1(X)`. Поэтому замена - это `TPCMPAD1(X)` -> `TPCMP1I(X, k)` с явным номером слота. Занятые слоты: `[3]`, `[8]`, `[11]`, `[13]`, `[31]`, `[39]`, `[160]`, `[161]`. Свободные проверенные: `[10]`, `[12]`, `[14]`, `[16]`.

`DataSeg` в исходниках нигде не передаётся: он скрыт внутри PC-обёрток `10_14/FILES/COMTUP.PAS`. Правок по этой причине нет.

## Удалённые имена

`TPCMPADR` и `AROP` в верхних слоях не вызываются. Они остались только в объявлениях старых `COMTUP`, в генераторе `TPREDT.PAS:870,874-876,883` и в **несовместимой с новым модулем** деке `tests/comtup_test.b6` (строки 14, 20, 32, 38). `AROP` в `TPCX.INC:92` - поле записи, правке не подлежит.

## Числовые PIC-коды

`PicCode` декодирует только младший байт `TPCMPIN1`. Живые вызовы, которые сейчас не отображаются:

- `29`, `541`, `1821`, `2845`, `5405`, `7453`, `7709`, `8221`, `9245`, `16925`, `19229` -> младший байт `29` (`ex`), `PicCode = 0`;
- `7429`, `7430`, `7432` -> op 5/6/8, не отображаются;
- `7438` -> op 14, 15 живых вызовов в `TSSPPR`;
- `7513`, `7514` -> op 89/90, не отображаются.

Объём полного перевода: `UCOMPAS` - 82 `TPCMPP1` + 21 `TPCMPIN1` + 4 `TPCMPL1`; `TSSPPR` - 295 + 48 + 9. Итого около 459 вызовов, 142 различных слова. Механической замены чисел на коды МАРС быть не может.

## Минимальный набор для CGetBdKey

Более дешёвый путь для первого прогона - не трогать верхние слои, а собрать отдельную декy, повторяющую `UCOMPAS.PAS:103-111` на `COMTUP` напрямую. Тогда правки 1-3 не нужны.

Если же править `UCOMPAS`:

1. строки 103, 104 -> `TPCMP1I(Number, 10)`, `TPCMP1I(R, 12)`;
2. переименовать остальные 22 живых вызова, иначе модуль не соберётся;
3. `UNPIC.PAS:159` -> `TPCMP1I(jj, k)`;
4. добавить в `PicCode` op 90 - реальную операцию чтения бд-ключа;
5. создать фикстуру с известным бд-ключом и объявить `PROGRAM ...(OUTPUT, BDVECT, BDERRN)` в тесте.

## Риски

- Типы: `var`-параметр требует точного совпадения. `word`, `TYPEM`, массивы и `char` обёрток не имеют.
- Несуществующие имена: любая необновлённая дека или сгенерированный `TPREDT` даст unresolved external. 19-й вход - предел, один алиас `TPCMPAD1` не покроет четыре типа.
- COMMON `BDVECT`/`BDERRN` должны быть объявлены в главной программе, иначе «ЗАТЕРТО СПО».
- `CmpsOk` читает `CoctPtr^`, который выставляется только в `COpen`; без `COpen` тест упадёт до проверки `R`.
- ~~Главный блокер: `PicCode(7514) = 0`~~ **снят**: op 90 реализован через op53, `R = 3072` при `BDERRN = 0` (`CGETBDKEY-TEST.md`). Остаётся нереализованным op 89.
