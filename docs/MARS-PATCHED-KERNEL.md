## 1. Подготовка (факт)

`md5_backup_manifest.txt`. После всех прогонов md5 оригиналов в `~/.besm6`

## 2. Проверка предложенной вставки в исходник (факт)

Взят `re-mars-fixed.asm` (три константы уже исправлены для компиляции) и
вставлен патч из `re-mars-limit-1024.patch` строго после `ЗП DBLEN`
(`re-mars-patched.asm`). Компиляция проверенным рецептом дала 0 ошибок,
874 слова вместо 873. Анализ листингов `out/fixed/` и `out/patched/`:

- все 93 метки после точки вставки сдвинулись ровно на **1 слово**;
- точки входа `START`, `SWITCH`, `MKCTL`, `OVERFL`, `PR1022` не сдвинулись;
- M13-смещения (`BDBUF-BDVECT = 16₈`, `BDTAB-BDVECT = 17₈`) сохранились;
- новые слова не затирают буферы: они попадают в конец модуля (03604).

Прогон пороговых колод с этой сборкой (`logs/patched_len_*.run`,
`results_inplace.tsv` первая серия) показал **регрессию уже на 1000 зонах**:
1000 - зависание с 95 % CPU (процесс убит через ~12 мин), 1023 -
`ЗАПРЕЩ.КОМАНДА`, 1024/1025/1026 - `КОНТРОЛЬ КОМАНДЫ`, печати `MARK` нет.
То есть сдвиг адресов недопустим, несмотря на сохранение относительных
смещений. Гипотеза (не доказана): загрузчик МАРС использует либо фиксированную
длину модуля, либо абсолютные адреса, не пересчитанные транслятором; сдвиг
на 1 слово делает загруженный образ несовместимым с настройками M4/M13.

Дополнительно обнаружена **семантическая ошибка самого патча** (факт по
`besm6_cpu.c:1195,1594` и по эксперименту): `НТЖ` - побитовое XOR, а `ПО`
после него переходит при нулевом результате, то есть при `DBLEN == 1024`.
Проверка `НТЖ E11; ПО OVERFL`, перенесённая в трамплин без сдвига, выдала
`06 ПЕРЕПОЛНЕНА` на 1024 и по-прежнему падала на 1025 (`logs/inplace_len_*`).

## 3. Итоговая правка на месте (факт)

Правка наложена на бинарник зоны 0657 (`apply_inplace_patch.py`,
`inplace-patch.asm`). Все адреса модуля остаются прежними:

- `03440`, вторая половина слова: `УИ M5` заменено на `ПБ 03720`;
- свободные слова `03720..03722` (в эталоне нули, в таблице символов
  отсутствуют, находятся за резервом `ПАМ 124`) содержат трамплин:
  `УИ M5; СЧ E11; ВЧ DBLEN; ПЕ OVERFL; ПБ 03441`;
- `ВЧ DBLEN` формирует `1024 - DBLEN` в аддитивном режиме, `ПЕ` переходит
  при отрицательном результате, то есть строго при `DBLEN > 1024`;
- при срабатывании вызывается существующий `OVERFL` (02570) -> диагностика
  `06 ПЕРЕПОЛНЕНА`, clamp не делается; при нормальном продолжении управление
  возвращается на 03441 (`СЧ DBDESC`, `И E18П1`).

Изменено ровно 4 слова зоны: 03440, 03720, 03721, 03722. md5 зоны 0657
(1024 слова): `6be325a8143c5256dc0e7a8888cff728`; md5 18-зонного дампа
`b0b34efe612a7bff0951b48ffa10e44f` (эталон `1e0371b054f29adc7804d982bd8b3de6`).
Запись выполнена через `besmtool write 2348 --start=0657`; обратный dump
(`out_zone/inplace2-readback.bin`) байтово совпал с записанным файлом.

## 4. Пороговые колоды (факт)

Команда: `dispak --path=. -p deck.b6`, перед каждым прогоном диски
восстанавливались из `backup/`, 2348 брался из `inplace2-2348.master`.

| Дека (длина, 10) | exit | Диагностика | `MARK … ERR` | `EXN` | `КОНТРОЛЬ КОМАНДЫ` / PC=00000 |
|---|---|---|---|---|---|
| 1000 | 0 | как в эталоне | 5 | 0 | нет |
| 1023 | 0 | 02 + 05 | 5 | 0 | нет |

Вывод 1000/1023/1024 байтово совпал с контрольным логом
(`mars-length-threshold/logs/len_*.run`) - `diff` пуст. Для 1025/1026/1750
печать достижима, `КОНЕЦ ЗАДАЧИ` есть, stderr пуст, `EXN=0`.

Отдельно сгенерированы колоды `decks/diag_newd_*.b6`, где `BDERRN` печатается
сразу после `NEWD`, до `OPEND`. Результат: 1024 -> `ERR=2`, 1025/1026/1750 ->
`ERR=6`. В стандартных декаках `OPEND` после `NEWD` перезаписывает `BDERRN`
значением 5 (это же происходит и на 1000 зонах в контрольном опыте),
поэтому финальный `MARK` показывает 5. Требование `BDERRN=06` выполнено
в диагностическом срезе сразу после `NEWD`; в чистом виде после `OPEND` оно
не достигается без изменения самих колод или семантики `OPEND`.

## 6. Гипотезы и точка остановки

- Гипотеза (не проверена трассировкой): причина отказа вставки - фиксированная
  длина загрузки модуля или неявная абсолютная адресация в загрузчике.
- Гипотеза: свободные слова 03720..03722 доступны именно на этой конфигурации
  образов; на другой сборке ДИСПАК их нужно перепроверить по дампу и таблице
  символов до наложения патча.
- Факт: `BDERRN=6` виден только до `OPEND`; после `OPEND` значение 5.
- Остановка: работа завершена в scratch. Репозиторий `re-compass` не тронут,
  исходные образы не изменены, коммит/push не выполнялись. Дальнейшие шаги
  (перенос правки в исходник с сохранением адресов, пересборка эталонов зоны,
  полное доказательство причины сдвига) требуют отдельной команды.
