# Рецепт внешних Pascal-процедур по образцу arfalib

Механизм проверен в `~/Yandex.Disk/dispak/tests/arfalib/`. Используем его для `COMTUP`, а не изобретаем новый инструмент.

## Как устроены внешние процедуры

Объявление в модуле (`arfalib.pas:36-39`):

```pascal
procedure ENCCTR(c2: CtxT; txt: PtrW; r2: PtrW;
  l2: integer; iv: integer); external;
```

Экспортируемые точки помечаются `(*=e+*)` перед заголовком. Проверенный лимит - **19 входов** (20-я даёт ошибку 87); имена каталога не длиннее 8 букв. Набор из 17 процедур укладывается в лимит.

Реализация написана на Паскаль-Мониторе с машинными кодами через `besm(...)`, а не на ассемблере. Вызывающая программа объявляет те же имена снова как `external`; разрешение идёт по каталогу PERSO при загрузке.

Для ассемблерных и Fortran-модулей есть форма `PROCEDURE name(...); FORTRAN;` с `(*=F+*)`: параметры передаются по ссылке, проверка типов отключается. Именно так подключены `PASACD`, `PASSETAR`; `PASBDI`/`PASBD` объявлены как `EXTERNAL`.

Важное ограничение: глобальные переменные объектного модуля компоновщик размещает поверх данных вызывающей программы. Всё рабочее состояние держать в локальных переменных. `*BDVECT*` должен жить в главной программе и передаваться по ссылке.

## Сборка

Дека сборки (`arfalib-build.b6:1-9,213-218`):

```text
шифр 419999 зс5^
лен 40(2348-wr)^
лен 41(2196-wr)^
eeв1а3
*name
*call yesmemory
*perso:402570
*stand
*call *pascal
<текст src/comtup.pas>
*to perso:402570
*end file
``````
ЕКОНЕЦ
```

Тестовая колода отличается режимом томов (`лен 40(2348)^`, `лен 41(2196)^`) и хвостом `*execute` вместо `*to perso`.

Перед записью: резервная копия рабочего тома. Если библиотека вырастет за доступные зоны, использовать приём `*table:liblist(COMTUP)` + `*liblist:402540` -> `*to perso:402560`, затем в тесте `*perso:402570` и `*perso:402560,cont`.

## Проверка

- Баннер `PASCAL COMPILER 15.1 (28.10.26)`, отсутствие `15.0 (15.02.82)`.
- Отсутствие ошибок 84/12/52. Сообщение `ЧИСЛО ОШИБ. ОПЕРАТОРОВ 0000` относится к Fortran/DTRAN, Паскаль-Монитор его не печатает.
- `ДЛИНА LIBRARY <NNN> ЗОН` - восьмеричное число, включает два зонных каталога. После ARFALIB это `031` зона.
- Максимум **19** точек `(*=e+*)` на модуль; 20-я даёт `******87 МНОГО ВХОД ПРОЦ`. Подробности и проверенные логи: `BUILD-VERIFICATION.md`.
- При проверке каталога рабочей копии обязателен `BESM6_PATH=.`, иначе `besmtool` читает `~/.besm6/2348`.
- `besmtool view 2348 --start=1400 --length=2 --encoding=t` показывает новые входы.
- `bash tools/mars_check.sh` даёт `БАНДИТ зона 0657: PASS`.
- Сравнение вывода через `difflib.unified_diff`, где `#` в эталоне - wildcard.

Ложные ошибки 84/12/52 возникают из-за строк колоды длиннее 72 символов: `external`-объявления обрезаются. Проверять `awk 'length($0)>72{print FNR,length($0)}' *.pas`.

Уже есть в библиотеке 02570: `PASBDI`, `PASBD`, `PASBDE`, `PASACD`, `PASSETAR`, `PAIB`, `*BDC*`. Отдельная колода `*perso` для МАРС-обвязки не нужна.
