# Рабочая реализация COMTUP

Модуль `src/comtup.pas` скомпилирован и проверен на эмуляторе 23.11.2026. Все прогоны - на рабочих копиях дисков в `/tmp/.private/azizz/opencode/comtup-final/`; оригинальные образы не изменялись.

## Исправленные дефекты черновика

1. `MarsErrNo` удалён. Вместо него COMMON-параметр `BDERRN`; в режиме `s0` его внешнее имя - `*BDERRN*`. `EXN := BDERRN`, `CompassInstalled` проверяет `BDERRN = 0`.
2. Локальные массивы `bv` заменены COMMON-параметром программы: `PROGRAM comtup(output, BDVECT, BDERRN)`. Указатели PIC кэшируются в `BDVECT[160]/[161]` и переживают возврат из процедуры.
3. Нетипизированный `VAR P` заменён четырьмя типизированными входами `TPCMP1I/A/B/P(var p: integer/alfa/boolean/AnyPtr; k: integer)`. Каждая пишет `BDVECT[k].i := ord(ref(p))`.

Дополнительно по первому прогону исправлено:

- `cZav = 59c` - невосьмеричная константа, ошибка 20; удалена.
- `TPCMPAD1I/A/B/P` - 9 символов, каталог обрезает до 8; переименованы в `TPCMP1I/A/B/P`.
- Имя типа `BDVecT` совпадало с переменной `bdvect`; переименовано в `TBDVec`.
- Имена COMMON-параметров в заголовке должны совпадать с var; исправлено.
- `PicT.l` изменён с `alfa` на `integer`.

## Точки входа

18 входов `(*=e+*)`, предел 19. Состав: 11 реально вызываемых процедур, 4 типизированные обёртки, 3 заглушки. `TPCMPADR` и `AROP` удалены как неиспользуемые заглушки с нетипизированным `VAR P`.

Итог: 17 - 1 - 2 + 4 = 18. Все 11 реально вызываемых процедур сохранены.

## Исправления по аудиту и интеграционному тесту

Внесены в `src/comtup.pas` после первой успешной сборки:

1. `PicCode`: op 4 («найти первую») мапился в `cLast = 02c`, исправлено на `cFirst = 01c`. Аудит по `re-mars.asm` показал, что `02` - «в конец», а `01` - «в начало». op 11 («найти последнюю») мапится в `cLast` верно.
2. `TPCMPIN1`: op 90 (`7514`, `CGetBdKey`) возвращал `PicCode = 0`, поэтому `pasbd` не вызывался и `R` оставался `-1`. Добавлена проверенная последовательность: микрокоманда МАРС `op53 = 352453c` копирует бд-ключ из слота `[29]` в scratch-слот `[20]`, затем значение пишется по адресу из слота `[24]`.
3. Слоты для `CGetBdKey`: адрес `Number` - `[22]`, адрес результата `R` - `[24]`, scratch - `[20]`, бд-ключ - `[29]`. Обёртки принимают номер слота вторым параметром, поэтому вызывающий код обязан соблюдать это соглашение.

Пересборка после патча: баннер 15.1, `ДЛИНА LIBRARY 032 ЗОН`, каталог зоны 2570 содержит `COMTUP` с 18 входами, ошибок нет.

op 89 (`7513`) остаётся нереализованным: соответствие операции записи бд-ключа не установлено. op 59 (`zaver`) также остаётся гипотезой (`35c`).

## Идемпотентная инициализация SSBF5

Первоначальный `SSBF5` при каждом вызове обнулял `BDVECT`, вызывал `PASACD` и `PASSETAR`. Повторный `PASACD` после `newd/opend` перезаписывает описатель области и портит состояние МАРС, а обнуление `BDVECT` теряет бд-ключ в слоте `[29]`.

В `src/comtup.pas` инициализация сделана условной по признаку `BDVECT[36]` (там лежит info word области после `PASSETAR`):

```pascal
if BDVECT[36].i = 0 then begin
  for j := 0 to 167 do BDVECT[j].i := 0;
  i := 1270000c;
  PASACD(i);
  PASSETAR(270000c)
end;
pasbdi;
BDVECT[3].i := 0
```

`pasbdi` выполняется всегда, число входов осталось 18. Проверено: при фикстуре, созданной до вызова внешнего `SSBF5`, слот `[29]` сохраняется, `R = 3072`, `BDERRN = 0`.

## Переименование вызовов в верхних слоях

При интеграции с `UCOMPAS.PAS` и `TSSPPR.PAS` вызовы `TPCMPAD1` заменяются на имена оберток из этого модуля:

| Обёртка в `src/comtup.pas` | Тип аргумента | Примеры вызовов |
|---|---|---|
| `TPCMP1I` | `integer`, `longint`, `CmpsAddr` | `UCOMPAS.PAS:85,86,103,104,121,122,137,150,151,162,174,187,201,215,229,243,267,282,299,313,328,344`; `TSSPPR.PAS:216,267-269,272,403-406,630,649,667,677,687,697,714,729,786,823,875` |
| `TPCMP1A` | `alfa`, `alf6` | `TSSPPR.PAS:836,886`; возможно 402, 621 (требует проверки объявлений) |
| `TPCMP1B` | `boolean` | `TSSPPR.PAS:762,787,270`; возможно 849, 899 (гипотеза) |
| `TPCMP1P` | `pointer` | `UCOMPAS.PAS:377`; `TSSPPR.PAS:963` |

`UCOMPAS.PAS:281` (`VAR Key` в `CFindByKeyElement`) - гипотеза: `integer`, тип задаётся `EType`, нужно уточнить по `UCMPSN.PAS:612`. Неактивные вызовы: `UCOMPAS.PAS:71,72,399`.

Ограничение имён: идентификаторы длиннее 8 символов обрезаются, поэтому в модуле использованы 7-символьные имена. Подробности эксперимента: `BDVECT-ADDRESS.md`.
