## 2. Принципы

- Каждая дека запускается **целиком**, без выборочного выполнения отдельных строк. Допускается только адаптация системных карт `*CMP`/`*SERVIS`, как в `original_deck_front.b6`.
- SERVIS-операторы и ЯОД/ЯМД-тексты не изменяются.
- Все прогоны идут на рабочих копиях дисков; оригиналы не трогаются.
- Эталон - полный stdout `dispak`, с нормализованной датой баннера (`DD.MM.26`).
- Результат каждой декы кладётся в `gold/output/deckNN-<имя>.out`.
- Статус меняется только по факту: exit 0, пустой stderr, отсутствие `******`, осмысленный вывод, `EXN=0`.

## 3. Этап А. MAD-деки 3, 8, 9

Расширить `src/genmad.pas` / MAD-интерпретатор до полного набора операций из дек:

- `HAЙTИ ПEPBYЮ / CЛEДYЮ / ПPEДЫД / ПOCЛEД / BЛAДEЛ / ПO-KЛЮ`;
- `ECЛИ COC <n> ... TO ...`, `K;` (условия и переходы);
- `ЗAMEHИ БД-KЛЮ`, `BЗЯTЬ БД-KЛЮ`;
- `BЗЯTЬ`, `BЫДATЬ`, `KOHEЦ`.

Порядок:

1. Извлечь строки 169-189, 637-667, 669-695 из gold через `tools/severov/extract_gold.py`.
2. Построить деку с загрузкой данных (из готовых `ADA/SC/ZPROC/BPEMEH` или через `PUTD`) и полным MAD-циклом.
3. Прогнать, сверить вывод с текстом дек (ожидаемые ключи/значения).
4. Зафиксировать `deck03-mad-output.out`, `deck08-mad-unload.out`, `deck09-mad-unload.out`.

Критерий: все команды MAD из дек выполняются, `EXN=0`, вывод содержит ожидаемые записи.

## 4. Этап Б. Схемы 4 и 10

Использовать `src/ttc15.pas` на строках 191-318 и 697-879. Возможные расширения парсера:

- `TИП ... PAЗMEP`, `ЗAПИCЬ ... ЭЛ`, `HAБOP ... ЧЛEH/BЛAДEЛ/ПPИBЯЗ/YПOPЯД`;
- `BAPИAHT`, `ДУБЛЬ`, `PEЖИM` в `ОБЛACTЬ`;
- таблица кодов ЯМД 01-17 в конце описания (строки 308-316, 868-876).

Критерии: `deck04-schema-am.out`, `deck10-schema-zat.out` содержат список типов/записей/наборов и 0 ошибок.

## 5. Этап В. Fortran-стартап (дека 5)

Строки 319-377: `PROGRAM`/`COMMON`/`CALL LOADGO`/`ENTRY CK/AM/ЗT`. Запуск через Дубнинский FORTRAN по образцу `gold_shtamp.b6`:

- извлечь текст деки, адаптировать только системные карты;
- скомпилировать и выполнить;
- проверить, что стартап завершается и передаёт управление (`ENTRY`).

Критерий: `deck05-fortran-startup.out` с `КОНЕЦ ЗАДАЧИ`, без ошибок трансляции.

## 6. Этап Г. Прикладные Pascal-программы (деки 12-14)

18 программ с `&&...&&` требуют полного парсера ЯМД. Текущий `src/predtgen.pas` - только генератор операций. Необходимо:

1. Перенести на Паскаль-Монитор цепочку `TSSBAS`, `TSLM`, `TSSDMPR`, `TSSDML`, `TSPIC`, `TSSERR`, `TSSZT` из `10_09_TURK/FILES/TURK.ARJ`.
2. Восстановить типы `TYPPIC`, `TYPEM`, `TEKOP`, `TRN`, `NAM`, `SLANGM`, `PUTEOL`, `PUTALF` (сейчас 163 диагностики в `src/tsspr.draft.pas`).
3. Реализовать `OPBIB` с формальными параметрами (в исходнике сигнатура закомментирована).
4. Подключить реальный `TSERVIS`/`COMTUP` вместо прямых МАРС-примитивов.
5. Написать front-end, который читает PROGRAM из деки, заменяет `&&...&&` на вызовы сгенерированных процедур и исполняет программу.

Порядок запуска: сначала по одной программе из каждой деки (`SKLMON`, `AMOHED`, `ZATHED`), затем остальные 15.

Критерий: 18 файлов `deck12-skmon.out`, `deck12-skl-otd.out`, ..., `deck14-zattab.out`; у каждого exit 0, stderr пуст,печать программ (меню и отчёты), `EXN=0`.

## 7. Порядок выполнения и зависимости

| Этап | Зависимости | Оценка |
|---|---|---|
| А (MAD) | готовый `genmad`, загрузочные данные | 1-2 дня агентского времени |
| Б (схемы) | `ttc15` | 0,5-1 день |
| В (Fortran) | Дубнинский FORTRAN, образец `gold_shtamp` | 0,5 дня |
| Г (18 программ) | этапы А, Б + порт цепочки TSS | 4-7 дней |

Этапы А, Б, В независимы и могут идти параллельно. Этап Г зависит от результатов А и Б.
