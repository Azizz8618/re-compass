## Что такое TTC (факт из исходника)

`Unit tTC` с единственной экспортируемой процедурой `SStc`. Заголовок:

```pascal
USES comtup, Tservis;
Implementation
USES TSSBAS, TSSDMPR, TSSERR, TSSISHP, TSLINF, OpDos, oPCRT, OpString;
```

TTC не является самостоятельной программой: это модульotransлятор языка описания данных (ЯОД) КОМПАС, работающий поверх:

- `Tservis` / `comtup` - доступ к МАРС-областям и каталогу объектов;
- `TSSBAS` - глобальный указатель `ss^` типа `ZZSS` со всеми описательными структурами (`CX`, `AREA`, `RC`, `IT`, `ST`, `TYP`, `SYSTEM`, …);
- `TSLINF` - словарь `SLANGT[1..100]` (ключевые слова ЯОД) и тексты сообщений;
- макроподстановки `TPCMPP1(код)`, `TPCMPIN1(код)`, `TPCMPAD1(…)`, комментарии вида `(*+B+!)(!--*)` - это не стандартный Паскаль, аспецифичным препроцессором PC-ветки (гипотеза: макросредства Comfy/TSS, генерирующие проверки `COCT`/`ERC`; в исходниках `TTC.PRT` они уже развёрнуты в цифры).

Внутренние процедуры TTC и их роль (факт):

| Процедура | Роль |
|---|---|
| `SCHEM` | открытие/проверка схемы `CX.CXNM`,_area `SSCXEM`, прав доступа, parametры `PEЖИM`, вызов `PUTCXE` и `YPOBE2` |
| `PUTCXE` | запись служебных записей даты/времени в каталог |
| `YPOBE2` | главный цикл разборщика: `TИП`→`TYPP`, `ЗAПИCЬ`→`SREC`, `HAБOP`→`SSET`, `OБЛACTЬ`, `KOHEЦ`→`KONEC` |
| `TYPP`/`TYPCO` | объявление типа: базовый тип (`CИMBOЛ`, `ЦEЛОЕ`, `ДEЙCTB`, `TEKCT`, `ЛОГИЧ`, `KOHCИM`), `PAЗMEP`, вычисление `TYP.TL/TBL` |
| `SREC`/`PUTREC` | объявление записи, имя, `ЗAMOK`, поиск/создание в области, затем цикл `ITEM` до `;` |
| `ITEM`/`PUTIT` | поле записи `ЭЛ <имя> <тип> [PAЗMEP n] [KOHCИM]`, поиск или генерация типа `T*NNN`, атрибуты `METOД`, `KOHCИM` |
| `SSET`/`PUTSET` | объявление набора: `ЧЛEH`, `BЛAДEЛ`, `ПPИBЯЗ`, `YПOPЯД`, `BKЛЮЧE`, `ИCKЛЮЧ`, `ДYБЛИK`, `KOHCИM` |
| `LATER`/`ZPIT`/`POSSEL` | разбор «набора через» (`ИCПОЛ <запись>.<поле>`) и проверка прав |
| `KONEC` | финализация: нумерация наборов (`ST.STSM`), смещения полей (`IT.IBP/IRP`), длина записи `RC.RL`, печать |
| `NOVO`, `CLI`, `CLEA`, `UBRSCH` | создание/удаление схемы и очистка объектов |

Формат ввода - поток строк ЯОД (6-бит, 72 символа), терминатор `KOHEЦ.`; комментарии `?*…*`; разделители `, ; : .`. Формат вывода - печать служебных сообщений и списка объектов через `PUTALF`/`Writeln`. Состояние хранится в записанной области `SSCXEM` и в области схемы; `SYSTEM.NUMSS` нумерует генерируемые типы.

## Зависимости, которые нельзя перенести напрямую (факт)

- `ss^` - huge `ZZSS` record (~20 вложенных записей) в `TSSBAS`; без `TSSBAS`, `TSSLANG` и менеджера областей TSS новый код не соберётся.
- `TPCMPP1/TPCMPIN1/TPCMPAD1` - не определены ни в одной доступной `.pas`; это макросы, а не подпрограммы.
- `ERC/ER2` пишут в `ss^.COCT` и общий `ERROR`; семантика ошибок завязана на TSS.
- `Celoe2`, `Dejstv2`, `SLANGT` находятся в недоступных модулях (`TSSLANG`/`TSBASEP`); `SLANGT` удалось восстановить из `TSLINF.PAS` (таблица на 100 слов с английскими подсказками в комментариях).

## Реализация и проверка (факт)

Порт - **не построчный перенос TTC**, а новая программа `src/ttc15.pas` (~278 строк), реализующая описанное выше подмножество:

- разбор строк 72 символа, токенизация в `alfa` (6 симв.), числа до 8 цифр хранятся строкой (99999000 не влезает в 24-битный `integer`);
- три МАРС-области `CXHD` (заголовки), `CXFL` (поля), `CXAT` (атрибуты), info word `2270000c+1/2/3` при `PASACD(20270000c)`, `PASSETAR(270000c)`;
- ключ заголовка - имя объекта (6 симв.), ключ детали - первые 4 символа имени + 2-значный индекс;
- запись данных - `packed array[1..36] of char`, 6-символьные поля;
-control: `EXN=0`, `MARSERR=0`, 79 успешных `putd` (23 заголовка + 21 поле + 35 атрибутов), контрольные `getd` вернули корректные данные;
- вывод: `TYPES 2`, `RECORDS 8`, `SETS 13`, полный список полей и атрибутов.

Сборка: `PASCAL COMPILER 15.1 (28.10.26)`, 0 ошибок трансляции. Команда:

## Находки по Паскаль-Монитору 15.1 (факт, воспроизведено)

1. Глобальный раздел `const` перед `var` приводит к `******80 НЕ ОПРЕДЕЛЕН ВНЕШНИЙ ФАЙЛ` для heading-параметров `BDVECT/BDERRN/PIC`. После удаления `const` (константы заменены литералами) ошибка исчезла. В рабочем `src/servis.pas` глобального `const` нет.
2. Функция, возвращающая `packed array of char` → `******9 ТИП НЕ ДОЛЖЕН БЫТЬ ФАЙЛОВЫМ`. Заменена на `procedure … (var z:Num8)`.
3. Присваивание в Element двумерного массива `alfa` → `******33 НЕДОПУСТ ТИПЫ ПРИ ПРИСВАИВАНИИ`. Заменено на одномерный массив с индексом `(i-1)*12+j`.
4. Передача элемента массива в `var`-параметр → `******40 НЕСООТВЕСТСТВИЕ ТИПОВ ПАРАМЕТРОВ`. Заменено на локальные временные `alfa`.
5. Строковый литерал в вызове процедуры с параметром `alfa` → ошибка 40; литерал в присваивании требует ровно 6 символов.
6. Диапазон массива не может быть выражением (`1..20*12`) → `******130 ТРЕБУЕТСЯ OF`.
7. Info word `newd` должен соответствовать базе `PASACD`: `20270000c` + `227000x c`. Пара `20270000c`/`1270001c` даёт `DATA BASE ERROR 000025` при `opend`;сообщение об ошибке `002621` при `putd`.
8. Три области получили разные младшие цифры зоны (`...1c`, `...2c`, `...3c`). Попытка `...101c`/`...201c` (изменение поля ZZ) приводила к ошибке `000025` на второй области.
9. `opend` нужно вызывать перед каждой группой `putd`: «текущая область» сохраняется между циклами. Без этого заголовки уходили в последнюю открытую область.

## Ограничения и stopping point (факт)

- Не портированы `TPCMPP*`, `ss^`, вычисление смещений `IT.IBP/IRP`, длины `RC.RL`, генерация типов `T*NNN`, правило `НАСЛЕД`, проверки прав `ADA`, работа с `SSCXEM`, подсхемы и таблица ЯМД 01-17.
- Строки 156-167 деки (подсхемы CX-CK0/CX-БИБ) в прогон включены, но разборщик останавливается на первой `KOHEЦ.` (строка 153), что соответствует границе описания схемы.
- Значения `PAЗMEP` хранятся первыми 6 цифрами (99999000 → 999990) из-за формата `alfa`; полное 8-значное значение сохраняется во внутреннем `Num8` только во время разбора.
- Диски в `disks/` - резерв; рабочие копии в `work/`. Файлы томов после прогона побайтово не изменились (dispak работает с образом в памяти), поэтому межпрогонная персистентность МАРС не проверялась; проверка `getd` выполнена внутри одного прогона.
- Репозиторий `/home/azizz/Yandex.Disk/re-compass` не изменялся; коммитов и push не было.

## Гипотезы

- `TPCMPP1/TPCMPIN1` - макросы препроцессора Comfy, генерирующие проверки `COCT` с конкретными кодами; это объясняет, почему в `TTC.PRT` они представлены числами. Прямого подтверждения в доступных исходниках нет.
- Расхождение `TTC.PAS` из TUR и TURK (разница 15 байт) может быть связано с датой сборки и правками 1995 года; содержимое не сравнивалось построчно.
- Ошибка 80 при глобальном `const` - вероятно дефект 15.1 в функции сопоставления heading-параметров с `var`-объявлениями: `/pascal-re/pascompl.cc:8650-8675` сопоставляет их только в определённом контексте. Точная причина не установлена, обходной путь проверен экспериментально.
