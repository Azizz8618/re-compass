# Руководство пользователя СУБД КОМПАС на БЭСМ-6/simh

Это практическая инструкция по запуску заданий на восстановленном стеке КОМПАС. Все команды проверены 24.11.2026: полный прогон `make test-all` обрабатывает 122 колоды, из них 112 совпадают с эталонами, расхождений нет.

## 1. Что доступно

| Компонент | Зона 2348 | Назначение |
|---|---|---|
| `COMTUP` + `SERVIS` | 2570 | нижний уровень СУБД и процессор операторов SERVIS |
| `UCOMPAS` | 3350 | верхний уровень API COMPASS |
| `TSSDML` | 3260 | 13 операций ЯМД и разбор языка MAD |
| `TSSPPR` | 3300 | связывание Pascal-программ |
| `MADX` | 3370 | интерпретатор MAD для прикладных программ |
| GOSTLIB | 2560 | системная библиотека, не трогается |

Поддерживаются все 14 колод Северова и 18 прикладных Pascal-программ из колод 12-14.

## 2. Подготовка рабочего стенда

Никогда не работайте на оригинальных образах. Создайте отдельный рабочий каталог и рабочие копии:

```sh
REPO=~/Yandex.Disk/re-compass
RUN=~/.cache/kompas-run
mkdir -p "$RUN"
cp ~/.besm6/{2048,2053,2099,2148,2348} "$RUN/"
cp ~/Yandex.Disk/dispak/tests/disks/2196 "$RUN/"
cd "$RUN"
md5sum * > MANIFEST.md5
```

Наложите стандартный патч ядра МАРС только на рабочую копию:

```sh
bash "$REPO/tools/mars/patch_workdisk.sh" "$RUN"
```

Патч меняет 4 слова зоны `0657` и проверяет контрольные суммы зоны/дампа. Подробности: `docs/MARS-PATCHED-KERNEL.md`.

Соберите PERSO-библиотеку `COMTUP`/`SERVIS`, она нужна почти всем заданиям:

```sh
dispak --path="$RUN" -p "$REPO/tests/comtup_final_build.b6" > build.run 2> build.err
```

### Изолированный HOME для dispak

`dispak` ищет свободный слот в `$HOME/.besm6/input_queue`. Если общий каталог заполнен другими задачами, он отвечает `БУФ ПЕРЕП` и не выдаёт результат в стандартный вывод. Используйте отдельный HOME:

```sh
JH=~/.cache/kompas-home
mkdir -p "$JH/.besm6/input_queue"
HOME="$JH" dispak --path="$RUN" -p "$REPO/tests/compass-jobs/job-create.b6" \
  > run.log 2> run.err
```

## 3. Шапка задания

```
шифр 419995зс5^
лен 40(2348-630)^
лен 41(2348)^
ОЗУ 32^
ее в1а3
*name 
*call yesmemory
*perso:412570
*stand
*call *pascal
```

Что означает:

- `шифр 419995зс5^` - шифр задания;
- `лен 40(2348-630)^`, `лен 41(2348)^` - однодисковая схема 2348;
- `ОЗУ 32^` - объём памяти;
- `ее в1а3` - карта `EEB1A3`;
- `*name`, `*call yesmemory`, `*stand`, `*call *pascal` - стандартный мониторный каркас;
- `*perso:412570` - подключение собранной библиотеки `COMTUP`/`SERVIS`.

За шапкой следует исходник `src/servis.pas`, затем `*execute`, операторы SERVIS, `*end file`, ``````, `еконец`. Готовый каркас лежит в `tests/compass-jobs/*.b6`.

## 4. Операторы SERVIS

| Оператор | Действие |
|---|---|
| `ОБЛACTЬ`, `ПPOCTP`, `СОЗДАТЬ ОБЛАСТЬ` | создать область/пространство |
| `OЧИCTИ` / `ОЧИСТИТЬ` | очистить область |
| `OCBOБO` / `ОСВОБОДИТЬ` | освободить область |
| `BOCCTA` / `ВОССТАНОВИТЬ` | восстановить область и напечатать таблицу страниц |
| `ОБНОВИТЬ` | обновить пространство |
| `ДУБЛЬ <новое> НА <головная>` | создать дубль |
| `ОСВАБД` | записать каталог областей |
| `ЖУРНАЛ <имя> CБPOCИ/ЗАКРЕПИ` | сбросить или закрепить журнал |
| `УБРАТЬ ОБЛАСТЬ` | удалить область |
| `ИЗМЕНИТЬ ОБЛАСТЬ ... ДЛИНА` | изменить параметры области |
| `СОЗДАТЬ ПОЛЬЗОВАТЕЛЬ` | зарегистрировать пользователя |
| `СОЗДАТЬ ПРАВО ... ДЛЯ-ВЫ/ДЛЯ-МО` | выдать право |

Параметры: `ДЛИНА`, `НАПР`, `НАЧАЛО`, `ВИД`, `ВАРИАНТ`, `ДУБЛЬ`, `РЕЖИМ`, `ПАРОЛЬ`, `КОНТРОЛЬ`. Разделители `;`, `,`, `.`. Подробности: `docs/SERVIS-STAGE4.md`.

## 5. Типовые задания

### Создание БД

```text
OБЛACTЬ TESTDB:ДЛИHA 8 PEЖИM 0,
OБЛACTЬ TESTJ:ДЛИHA 6 ВИД ЖYPHAЛ;
ПPOCTP TESTP:ДЛИHA 4;COЗДAT
B OБЛACTЬ TESTP.ПPOCTP,
КОНЕЦ.
```

Ожидаемый результат: `NЕW АRЕА N=1..3`, `ЕХN=0`. Файл: `tests/compass-jobs/job-create.b6`.

### Редактирование БД

```text
OБЛACTЬ TESTDB:ДЛИHA 8 PEЖИM 0;
ПPOCTP TESTP:ДЛИHA 4;COЗДAT
ИЗМЕНИТЬ ОБЛАСТЬ TESTDB: ДЛИНА 16,
ДУБЛЬ TESTD2 НА TESTDB,
ОБНОВИТЬ TESTP,
B OБЛACTЬ TESTP.ПPOCTP,
КОНЕЦ.
```

Ожидаемый результат: `ОБЛАСТЬ ТЕSТDВ ИЗМЕНЕНА`, `ДУБЛЬ ТЕSТD2 СОЗДАН`, `ОБНОВЛЕНО ТЕSТР`, `ЕХN=0`. Файл: `tests/compass-jobs/job-edit.b6`.

### Удаление БД

```text
OБЛACTЬ TESTDB:ДЛИHA 8 PEЖИM 0;
ПPOCTP TESTP:ДЛИHA 4;COЗДAT
OCBOБO TESTDB,
OЧИCTИ TESTDB,
УБРАТЬ ОБЛАСТЬ TESTDB,
B OБЛACTЬ TESTP.ПPOCTP,
КОНЕЦ.
```

Ожидаемый результат: `ТЕSТDВ ОСВОБОЖДЕНА`, `ТЕSТDВ ОЧИЩЕНА`, `ОБЛАСТЬ ТЕSТDВ УБРАНА`, `ЕХN=0`. Файл: `tests/compass-jobs/job-drop.b6`.

Важно: имя пространства создаётся только строкой `ПPOCTP <имя>:ДЛИHA n;COЗДAT`. Если его заранее объявить отдельной строкой `OБЛACTЬ`, будет `ОШИБКА 80: ОБЪЕКТ УЖЕ ЕСТЬ`.

## 6. Подлинная колода Северова

Для подачи 41 строки исходной колоды без `*CMP`/`*SERVIS` используется адаптер `src/servis_front.pas` и колода `tests/original_deck_front.b6`. Он отфильтровывает системные карты и передаёт операторы SERVIS порту. Подробности: `docs/ORIGINAL-GOLD-DECK.md`, `docs/COMPASS-JOB-TEMPLATE.md`.

## 8. Контроль зон и безопасность

- Никогда не меняйте `~/.besm6/*` и `/usr/local/share/besm6/*`. Эталон 2348: `b287267fe6163e7c5bf7fdd15a802ee0`.
- Зона `2560₈` содержит GOSTLIB и не используется нашими сборками.
- После каждой записи запускайте `python3 tools/check_zone_changes.py "$RUN/2348"`. При `UNEXPECTED` восстановите образ из резерва.
- Разрешённые диапазоны и их назначение: `docs/ZONE-ALLOCATION.md`.

## 9. Ограничения

- Это рабочая реконструкция на Pascal-Мониторе 15.1, а не подлинный компилятор `ЗMП` и монитор НИС Гидропроект. Системные карты `*CMP`/`*SERVIS` оригинальной колоды не исполняются, для неё имеется адаптер.
- Исторические стоимостные области `SY-HAK`, `ИC-ЗAT`, `ЭT-ЗAT` в архиве отсутствуют. В ZATTAB по решению пользователя стоят детерминированные заглушки `STUBV`, они не являются историческими данными (`docs/TSS-W10-STUBS.md`).
- Дека 5 (`CTAPT`) работает на заглушках подпрограмм.
- Повторный вход `DML(TRUE)` в исходной цепочке TSSDML даёт `STACK OVERRANGE`; прикладные программы используют проверенный путь через MADX.
- Подлинная бинарная совместимость с модулями 1989 года не подтверждена.
