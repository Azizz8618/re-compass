# Интеграционный тест CGetBdKey

Подготовка теста для проверки связки КОМПАС(Pascal) + МАРС на диске 2348. Шаблон ещё не запускался, поэтому конкретные числа в нём не зафиксированы.

## Каноническая последовательность

`CGetBdKey` в `UCOMPAS.PAS:99-116`, комментарий: «взять бд-ключ %Number в R». Тело, строки 103-111:

```pascal
TPCMPAD1 (Number);
TPCMPAD1 (R);
TPCMPP1  (36);
TPCMPP1  (0);
TPCMPP1  (19712);
TPCMPP1  (36);
TPCMPP1  (512);
TPCMPP1  (16896);
TPCMPIN1 (7514);
```

Тот же блок есть в `CMPSNO.PAS:395-404`, то есть это каноничная последовательность, а не опечатка. После вызова: `if CmpsOk then CGetBdKey := R else CGetBdKey := NoCmpsAddr`. `CmpsOk = (CoctPtr^ = 0)`, `NoCmpsAddr = 0`.

## Декодирование слов PIC

`W(low,high) = (high shl 8) or low`, младший байт - первая микрокоманда.

| Число | hex | Байты | Операция по `MICROCOD.TXT §4.1.6` |
|---:|---:|---|---|
| 36 | 0x0024 | (36, 0) | 36 `varlo` |
| 0 | 0x0000 | (0, 0) | ноп |
| 19712 | 0x4D00 | (0, 77) | 77 `mgth`, взять из n-й |
| 36 | 0x0024 | (36, 0) | 36 `varlo` |
| 512 | 0x0200 | (0, 2) | 02 поиск по ключу |
| 16896 | 0x4200 | (0, 66) | 66 `mgfal`, взять из tretia |
| 7514 | 0x1D5A | (90, 29) | 90, обратное op.89, плюс 29 `ex` |

`CPutBdKey` отличается только последним словом: `7513 = (89, 29)`. По симметрии get/put op90 - чтение бд-ключа, op89 - запись (гипотеза).

## Механизм на МАРС

- `TPCMPAD1(Number)` и `TPCMPAD1(R)` -> `BDVECT[k1].P := REF(Number)`, `BDVECT[k2].P := REF(R)`, слоты обязательно разные.
- `TPCMPIN1` -> `bdvect[3].i := <код>; pasbd;`.
- Рабочие слоты по `experiment.b6:61-67`: `[3]` микрокоманда, `[8]` ключ (6 символов), `[11]` адрес данных, `[13]` длина в словах, `[31]` результат, `[39]` длина.
- Гипотеза мостика: op90 соответствует МАРС-операциям над `BDVECT` в диапазоне 50-54 либо `find(11c)` + чтение `[31]`. Не доказано.

## Критерии приёмки

Обязательные поля: `BDVECT[3]`, `[8]`, `[11]`, `[13]`, `[31]`, `[39]`, `*BDERRN*`/`COCT`, плюс два разных слота под адреса.

Недопустимо:

- пустой или мусорный `[3]`;
- ключ короче 6 символов или с ненулевым 48-м разрядом;
- `[13] = 0` или меньше реальной длины: ошибка `14 ДЛ.ЗАП>ДЛИН`;
- коллизия слотов `[8]`, `[11]`, `[13]`, `[31]`, `[39]`;
- неинициализированный `BDVECT`: «ЗАТЕРТО СПО».

Дискриминатор ошибок:

- **МАРС не инициализирован**: падение на `PASBDI`/первом `PASBD` с «ЗАТЕРТО СПО» или `01 НУЛ.УКЛЮЧ`, `*BDERRN*` содержит мусор, дамп показывает, что `BDVECT` не обнулился. Лечится `PASACD` + `PASSETAR` + `PASBDI`.
- **Неверный микрокод**: `PASBD` возвращает осмысленный воспроизводимый код из таблицы ошибок (`03`, `14`, `16` и другие), `[3]` корректен, дамп стабилен, `R` содержит 0 или не тот ключ.

## Ожидаемый вывод

`R` равен заранее известному бд-ключу записи, код ошибки 0. При отсутствии записи `R = 0` и код `03 НЕТ ЗАПИСИ`.

## Однодисковая схема монтирования

Пользователь указал, что 2348 - это диск 2048. Проверено: зона `630₈` на 2348 байтово идентична зоне `630₈` на 2048 (md5 `d418e27188e7e0f6b58cbe52b5eb4966`). Поэтому код МАРС можно брать с того же тома:

```text
лен 40(2348-630)^
лен 41(2348)^
*perso:412570
```

С этой схемой inline-тест `tests/cgetbdkey_single.b6` даёт `R = 3072`, `BDERRN = 0`. Все 18 внешних имён `COMTUP` тоже разрешаются (`tests/comtup_final_test.b6` с подставленными LU). Прежняя схема `лен 40(2048-630)^` + `лен 41(2348)^` более не требуется.

## Фактические результаты

Тест проведён на рабочей копии 2348 в scratch `/tmp/.private/azizz/opencode/cgetbdkey-work/`. Оригинальные образы не изменялись.

Фикстура: `PASACD(1270000c)`, `PASSETAR(270000c)`, `newd('bdkey ',1270001c)`, `opend('bdkey ')`, `putd('kbd001', m)` с данными `111111 222222 333333 444444`. Бд-ключ получен микрокомандой МАРС op53: слово `352453c` копирует `BDVECT[29]` в `BDVECT[20]`.

```text
AFTER FIND slot29= 0000000000006000
AFTER FIND slot31= КВD001
BEFORE slot20= 0000000000000000
WORD= 0000000000352453
AFTER slot20= 0000000000006000
```

Бд-ключ записи `kbd001`: `6000₈ = 3072₁₀`. Для второй записи `kbd002` - `10000₈ = 4096`.

Тест канонической последовательности до патча:

```text
EXPECTED BDKEY= 0000000000006000
PIC NC= 0 NA= 4
SLOT29= 0000000000006000
R= -1 BDERRN= 0
```

`PicCode(7514) = 0`, `pasbd` не вызывался, `R` остался неинициализированным. После патча (`op53` + запись по адресу из слота `[24]`):

```text
EXPECTED BDKEY= 0000000000006000
SLOT29= 0000000000006000
R= 3072 BDERRN= 0
```

Тест проходит. Патч перенесён в `src/comtup.pas`; колоды и эталоны: `tests/cgetbdkey_fixture.b6`, `tests/cgetbdkey.b6` и соответствующие `.expected.txt`.

### Внешний COMTUP

Исходный `tests/cgetbdkey_external.b6` давал `R=0` по двум причинам: неидемпотентный `SSBF5` и фикстура, созданная в другой деке. После исправления `SSBF5` (проверка `BDVECT[36]`) и создания фикстуры в том же процессе тест `tests/cgetbdkey_external_fixed.b6` даёт:

```text
EXT FIXTURE S29= 0000000000006000
EXT AFTER SSBF5 S29= 0000000000006000
EXT R=      3072 BDERRN=         0 EXN=         0
```

Модуль пересобран: баннер 15.1, `ДЛИНА LIBRARY 032 ЗОН`, 18 входов, ошибок нет.

## Расхождения с планом

- Бд-ключ находится в слоте `[29]` (`ADESCR`), а не в `[31]`; `[31]` содержит alfa-ключ.
- op90 реализуется через op53 + запись по адресу, а не через МАРС 50-54 или `find` + `[31]`.
- Слоты для двух адресов выбраны `[22]` (`Number`) и `[24]` (`R`), scratch - `[20]`.
- Конфликт монтирования снят однодисковой схемой (зона `630₈` на 2348 идентична 2048). Inline- и внешний тесты проходят на одной диске.

## Что остаётся неизвестным

1. op89 (запись бд-ключа) остаётся нереализованным; `CGetKnotByKey` использует `7513`, как и `CPutBdKey`. Возможна ошибка в оригинале или более тонкая семантика.
2. считается ли op53 исторической реализацией op90 или только нашей рабочей заменой, не доказано.
3. тождество `COCT` (PC) и `*BDERRN*` (МАРС).
4. историческая семантика слов с ненулевым старшим байтом (`19712`, `512`, `16896`) не восстановлена: `PicCode` смотрит только младший байт, поэтому поиск в них не повторяется, а слот `[29]` живёт со времени `FIND` в фикстуре.
