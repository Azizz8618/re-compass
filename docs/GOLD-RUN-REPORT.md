## 2. Кодировка исходников

Факт: оба файла `gold/*.txt` - UTF-8 с BOM и CRLF, с частичной транслитерацией кириллицы латиницей (`ШИФP`, `ЛEH`, `OЗY`).

Факт: транслитерацию исправлять не нужно. В `dispak/dispak/encoding.c`, таблица `unicode_to_gost()`, латинские A, B, C, E, H, K, M, O, P, T, Y, X и соответствующие кириллические А, В, С, Е, Н, К, М, О, Р, Т, У, Х отображаются в один и тот же код ГОСТ 10859. Поэтому `ШИФP` и `ШИФР` читаются монитором одинаково. Проверено прогоном (см. run5).

Факт: BOM допустим (`utf8_getc()` пропускает 0xFEFF), а CRLF недопустим. Дека с CRLF (run9-crlf) падает:

```
   АВВД   НПК    НС   НСТ   СИМ ШИФР 419999000000
  04027    91     0     0   377 НЕТ КОНЦА ВВОДА
*** stack smashing detected ***: terminated
exit=134, out.run=0 байт, out.err=174 байта
```

Рабочий рецепт: `read_text(encoding='utf-8-sig')`, `.splitlines()`, записать с `newline='\n'`. Альтернатива, проверенная в run10-cp866: `iconv -f UTF-8 -t CP866 deck.b6 > deck.cp866` и запуск с `--input-encoding=cp866`. Вывод побайтно совпадает с UTF-8 вариантом (md5 `671224520cf82d4e3994aa7af5c3af03`). `besmtool` для conversions текста не нужен, он работает с образами дисков.

## 3. Попытка запустить подлинную колоду КОМПАС

Взята первая программа из `KOMPAS-based systems...txt`, строки 1-41: `*NAME ПРОСТРАНСТВА НИСА`, `*CMP`, `*SERVIS`, описание областей, `КОНЕЦ.`. Строки листинга, начинающиеся с `?`, удалены; `*END F` оставлен.

run1, исходный паспорт `ШИФP 410900 ЗMП^ЛEH 31(1C)^`:

```
cd runs/run1
dispak --path=. -p deck.b6 > out.run 2> out.err; echo $?
exit=1
out.run: 0 байт
out.err:
   АВВД   НПК    НС   НСТ   СИМ ШИФР 410900000000
  00000     1     0     0   057 НЕТ СТПАСП
```

Причина (факт по коду `dispak/vsinput.c`, `passload()`): двухбуквенный код СТПАСП `MП` ищется в таблице паспортов на диске 2053, зона 0543. В имеющейся таблице его нет. Требуется носитель с локальным монитором НИС ГИДРОПРОЕКТ (в деке `ЛЕН 31(1C)`, том 28 восьм., то есть 28decimal), которого среди доступных образов нет.

run2: замена кода монитора на стандартный `зс5` дала `НЕТ КОНЦА ВВОДА`, так как в подлинном листинге нет завершающих карт пакета. run3: добавлены

```
``````
еконец
```

после `*END F`. Результат run3: `exit=0`, `out.run=3259`, `out.err=0`, но:

```
*NАМЕ ПРОСТРАНСТВА НИСА
           *СМР

То есть монитор-80 не знает системных карт `*CMP`/`*SERVIS` и передаёт текст КОМПАС компилятору ФОРТРАН. Компилятора КОМПАС и его словарей на доступных дисках нет. ## 4. Рабочий контрольный пример из gold

Чтобы прогнать его без графической библиотеки с LU 67, к тексту gold добавлены только:

- главная программа `PROGRAM GSHT`, вызывающая `SHTAMP(0.,0.,0,0.)` и `SHTAMP(0.,0.,1,0.)`;

## 5. Оценка

Факт: подлинная программа из KOMPAS-файла не запускается в текущей среде из-за отсутствия локального СТПАСП и компилятора КОМПАС. Это подтверждено диагностикой и кодом `vsinput.c`.

Факт: подпрограмма `SHTAMP` из raznoe.txt компилируется стандартным ФОРТРАН-монитором и выполняется. Она строит контур штампа по табличным координатам: при `NS=0` это 11 линий и 30 точек, при `NS=1` - 3 линии и 14 точек; `L=0` задаёт горизонтальную укладку, `L>0` - вертикальную с инверсией Y. Все 44/58 числовых значений совпали с расчётом по константам исходника.

Вывод: `SHTAMP` пригоден как контрольный пример для проверки кодировки, формата колоды и ФОРТРАН-компилятора, но не как тест КОМПАС. Для теста КОМПАС нужен том с монитором `MП` и компилятор `*CMP`/`*SERVIS`, которых в доступном наборе образов нет.

Гипотеза: запуск исходных КОМПАС-деков возможен после восстановления таблицы паспортов на 2053 и копии системного тома 1C, но это требует носителей вне текущего набора.
