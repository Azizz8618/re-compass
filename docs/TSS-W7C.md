## 4. `TPCMPAD1(tt)`: слот и тип (эксперимент в scratch)

Факт 1: исторический `floppy/COMTUP.PAS` - только обёртка над `COMSST.OBJ`; там нет ни
номеров слотов, ни тела `TPCMPAD1(VAR P)`. Поэтому «исторический номер слота» не
существует: числа 63-92 - соглашение самого порта, присвоенное по порядку вызовов
(`patches/tsspr.patch`). Факт 2: `gold/TSSPPR.PRT:151-158` показывает макрос
`ВЗЯTЬ QU.QUT HA @tt`, то есть `tt` - **выходной адрес**, а не входное значение.

Слоты 63-92 уже заняты, 93 свободен (grep по `src/`, `tests/` не нашёл `BDVECT[93]`).
Семантика типизированных обёрток (`TPCMP1I/A/B/P`) такова: `BDVECT[k].i := ord(ref(p))`,
затем `SaveAdr(k)` кладёт этот адрес в `PIC.L[NA]`. Таким образом номер `k` - только
промежуточный держатель; существенен адрес `ref(p)`.

### Вариант А (испытан, не рекомендован): 19-й вход `TPCMP1M`

Добавлен тип `TYPEM = packed array[1..1344] of char` и вход
`(*=e+*)procedure TPCMP1M(var p:TYPEM; k:integer)` в конец `comtup.pas`; вызов заменён на
`TPCMP1M(tt, 93)`. Компиляция и линковка прошли: 19 входов, `ДЛИНА LIBRARY 032 ЗОН`,
0 диагностик. **Но** внутренние метки COMTUP сдвинулись: в `direct13_3260` адрес ошибки
`04266В` стал `04310В`, load-карта изменилась целиком, etalon дал DIFF. Это ровно тот сдвиг
меток, которого задание просит избежать. Вариант пригоден только с объяснённым
обновлением эталонов (`build/comtup-w7c.pas`, `logs/typed-*`).

### Вариант Б (рекомендован, испытан): переиспользование `TYPEMI` + `TPCMP1I`

В самом `tsspr-v12-linked.pas` уже объявлен проверенный тип
`TYPEMI = record case integer of 1:(I:integer); 2:(A:TYPEM) end`. Он даёт типобезопасный
адресный overlay без нового входа COMTUP:

```diff
--- a/src/tsspr-v12-linked.pas
+++ b/src/tsspr-v12-linked.pas
@@
-(* W1: COMTUP port dropped the untyped TPCMPAD1 entry ... *)
-procedure TPCMPAD1(var P:TYPEM); begin end;
-
 procedure TPCMP1I(var p:integer; k:integer); external;
@@ procedure CompileMethod;
-    tt:typem;
+    tt:TYPEMI;
@@
-TPCMPAD1 (tt);
+TPCMP1I(tt.I, 93);
@@
-  while tt[dlic]<>chr(C255) do
+  while tt.A[dlic]<>chr(C255) do
-      putchr(tt[dlic]);
+      putchr(tt.A[dlic]);
```

`ref(tt.I)` и `ref(tt.A)` - один и тот же адрес начала `TYPEM`, то есть семантика
макроса `HA @tt` сохранена; `SaveAdr` уже проверен тестом `TPCMP1I-ADDR-OK`. COMTUP не
меняется: 18 входов, `032 ЗОН`, лог сборки байтово совпадает с baseline (MATCH).
Патч скомпилирован и слинкован в scratch (`build/tsspr-v12-typemi.pas`,
`tests/tsspr-v12-typemi.b6`, `tests/tsspr3300-typemi.b6`), 4 целевые деки и 18 приложений
прошли. Единственное объяснённое обновление эталона: `tsspr-v12-linked.expected.txt`
включает полный листинг и load-карту, поэтому при принятии патча в репозитории этот
эталон нужно перегенерировать; финальные строки программы (`TSSPPR PORT V12`,
`КОНЕЦ ЗАДАЧИ`) совпадают побайтово, остальные три целевых эталона - MATCH без правок.
