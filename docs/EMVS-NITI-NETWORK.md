## 2. Схема в текстовом виде

ДРАКОН-схема Приложения 3 [P:4093-4131] имеет четыре ветви и два рекурсивных узла. Стрелки ниже показывают ветвление структуры, а не направление байт [H1].

```
ЕМВС НИТИ
├─ ЦВК
│  └─ ЦП БЭСМ-6 009 и 228
│     └─ ПОЛЕ ДИСКОВОЙ ПАМЯТИ КВП
│        └─ КАДОПАМ И КРК
│           └─ [СВЯЗЬ -> ЛУЧИ -> ТЕРМИНАЛЫ]  (рекурсия)
├─ СВЯЗЬ
│  └─ ЛС И РЛС, 7-Й КАНАЛ
│     └─ КАДОПАМ 2 МБАЙТ/С
│        └─ ДКС ЭЛЕКТРОНИКА-60
│           └─ [СВЯЗЬ -> ЛУЧИ]  (рекурсия)
├─ ЛУЧИ
│  └─ ИСПЫТАНИЯ АНИС -> ТРЕНАЖЕРЫ ДИАНА -> САПР ГАП АСУ -> СКП БАЗЫ ДАННЫХ
│     └─ ТЕРМИНАЛЫ
│        └─ КОНЕЦ
└─ ТЕРМИНАЛЫ
   └─ ВИДЕОТЕРМИНАЛЫ 15-ИЭ -> ДИСПЛЕИ МС-7401 -> КОНЕЦ
```

## 4. Граница КОМПАС / СУБД (F)

Верхние слои КОМПАС на БЭСМ-6 собираются с тома 2348: `COMTUP` + `SERVIS` в зоне 2570, `UCOMPAS` 3350, `TSSDML` 3260, `TSSPPR` 3300, `MADX` 3370, системная GOSTLIB 2560 не трогается [CU:5-16], [ZA:28-29]. Восьмеричная зона 2570 соответствует десятичной 1400 [D2348:23]. Нижний уровень это не PC-файлы, а система МАРС: ядро БАНДИТ в зоне 0657 тома 2348, каталог областей КОБЛА в зоне 630, доступ из Паскаля через стандартные процедуры [KB:21-26], [D2348:3-5], [D2348:35-52]. На PC-ветке `.ARE` это страницы по 2048 байт с дескрипторами [AD:1-18]; перенос на БЭСМ-6 идёт через генерацию колод с `PUTD` и проверкой `GETD` [AD:53-60].

Доступ к общему полю: обе БЭСМ-6 через КВП [P:4035-4037]; задача через ЭК 070 [P:811-815]; монопольный захват тома через ЭК 0157/0116 [P:819-821]; области АРФА через ЭК 063 с паролями [P:817-819]. Контроль зон 2348 ведётся побайтовой сверкой с эталоном [ZA:36-50], [CU:171-176]. Отчёт пользователь получает на АЦПУ через ЭК 064 [P:815-817], в dispak это печать в стандартный поток [P:869-870], после чего дамп и отчёт уходят по одному из трёх путей [R:11-17]. Риск чтения или подмены возникает именно на общем поле и на каналах, а не в верхних слоях КОМПАС: другая задача может прочитать зону или ленту, подменить слово в линии, повторить старый шифртекст [R:17]. Средства проекта защищают зоны при ЭК 070 имитовставкой [P:1645-1653], [G:72-75], а пароли и шифртекст помещаются на спецноситель 203 [R:21-24].

## 5. Типичный сеанс пользователя КОМПАС (F, по восстановленной среде)

1. Готовится рабочая копия томов, на неё накладывается патч ядра МАРС, собирается PERSO-библиотека `COMTUP`/`SERVIS` в зоне 2570 [CJ:6-14], [ZA:7-19]. Используется изолированный `HOME`, иначе dispak отвечает «БУФ ПЕРЕП» [CJ:16-17].
2. Готовится колода задания с шапкой: `шифр 419995зс5^`, `лен 40(2348-630)^`, `лен 41(2348)^`, `ОЗУ 32^`, `ее в1а3`, `*NAME`, `*CALL YESMEMORY`, `*PERSО:412570`, `*STAND`, `*CALL *PASCAL` [CJ:19-44]. План показывает тот же каркас и подключение библиотеки 02570 через `*PERSО:402570` [P:3908-3913].
3. За заданием следуют исходник на Паскале, `*EXECUTE`, операторы SERVIS, `*END FILE`, конец файла и «ЕКОНЕЦ» [CJ:43-44], [P:3901-3907]. Операторы `ОБЛACTЬ`, `ПPOCTP`, `СОЗДАТЬ ОБЛАСТЬ`, `ДУБЛЬ`, `ЖУРНАЛ` и другие меняют область, ожидаемый результат `EXN=0` [CU:83-100], [CU:102-144].
4. Данные читаются и пишутся через МАРС (`NEWD`/`OPEND`/`PUTD`/`GETD`), при импорте `.ARE` генерируется колода и выполняется пословная проверка [AD:53-60].
5. Выдача идёт на АЦПУ через ЭК 064 [P:815-817], в эмуляторе dispak печатается в стандартный вывод и сверяется с эталоном с нормализацией даты [P:869-870], [CU:163-169]. Отчёт `СКЛАД-88` и дамп области готовятся к передаче [R:11].
6. Передача идёт через общее поле, КАДОПАМ-ДКС/Электроника-60 или ленту [R:11-15]. Для защиты считается хеш открытого дампа `H0`, выполняется `ENCCTR` с ключом из пароля, шифртекст записывается через `ЗАП203` в раздел носителя 203, том освобождается ЭК 0116, целостность проверяется хешем [R:80-90], [R:103-110].

Ограничения учебного стенда: строки исходника не длиннее 72 байт, идентификаторы не длиннее 6 символов, зоны 0657 и 2560 не изменяются [R:137-142], [CU:171-176].

## 7. Гипотезы и расхождения (H)

- H1: стрелки ДРАКОН-схемы читаются как декомпозиция, а не как маршрут данных. Прямого пояснения в плане нет [P:4093-4131].
- H2: 2 Мбайт/с в плане и 16 16-разрядных слов/с в OSINT по К-71 не согласованы; это разные документы, выбирать значение без нового источника нельзя [P:4041] против [LO:51].
- H3: кто именно инициировал обмен по ЛС/РЛС через «7-й канал», в источниках не сказано. Отождествление «7-го канала» с модулем ОС СВЯЗЬ7 не подтверждено [P:4106], [DKS:12-14].
- H4: ДИАНА на М-220 из Приложения 3 и тренажёр К-71 «ДИАНА-БАРС» на СМ-2/Э-60/БЭСМ-6/7 описаны в разных документах; их тождество не доказано [P:4047-4048], [LO:23-35].
- H5: 8 каналов КРК в описании К-71 и 24 коммутируемые мини-ЭВМ к 1989 г. расходятся, объяснение в источнике отсутствует [LO:43-45], [LO:142].
- H6: перенос PC- Pascal-ветки КОМПАС на БЭСМ через МАРС это гипотеза реконструкции, а не исторический факт [KB:55-59]. Учебная легенда о передаче отчёта через КАДОПАМ-ДКС это модель угроз, а не подтверждённый исторический сеанс [R:11-17].
