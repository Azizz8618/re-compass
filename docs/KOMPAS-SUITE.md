# Интеграционный тест уровня СУБД (kompas_suite)

`tests/kompas_suite.b6` - воспроизводимый тест на реальном стеке Pascal-Монитор 15.1 + МАРС-6 + PERSO-библиотека `COMTUP`. Он проверяет осмысленное поведение уровня базы данных через внешние точки входа `COMTUP`, а не только прямую микрокоманду МАРС.

## Покрытые операции

| Проверка | Операция КОМПАС | Вызов | Ожидаемый результат |
|---|---|---|---|
| T01 | инициализация сессии | `SSBF5`, `EXN` | `EXN=0` |
| T02 | `CPlace` | `TPCMPIN1(7425)` | запись `kbd004` поставлена |
| T03 | `CFindFirst`, `CFindNext` x4 | `7428`, `7436` | обход `kbd001..kbd004` |
| T04 | `CFindByKey` | `7426` | найден `kbd003` |
| T05 | `CFindPreceding` | `7437` | найден `kbd002` |
| T06 | `CGetKnot`, `ITLEN` | `7440` | `11 22 33 44`, `ITLEN=24` |
| T07 | `CReplace` | `7439` | значение стало `101 202 303 404` |
| T08 | `CGetBdKey` | каноническая последовательность `UCOMPAS.PAS:103-111`, `7514` | `R=3072` |
| T09 | `CPutBdKey` | `7513` | `S29=10000₈`, повторное чтение `R=4096` |
| T10 | диагностика PIC | `APIC` | `NC=0`, `NA=16` |

Эталон: `tests/kompas_suite.expected.txt` (md5 `78f34a8cc41e717a83ce8a84ba2128e8`). Два последовательных прогона и прогон после пересборки `COMTUP` из `src/comtup.pas` дали байтово идентичный вывод.

## Воспроизведение

```sh
bash tools/run_kompas_suite.sh
```

Скрипт работает только с рабочими копиями дисков, перед запуском собирает `COMTUP` из репозитория в PERSO-библиотеку зоны `2570₈` рабочей копии 2348. Оригинальные `~/.besm6/*` и `/usr/local/share/besm6/*` не изменяются. Требуются образы 2048, 2053, 2099, 2148, 2348 и `2196` из `dispak/tests/disks` (переопределяется переменной `DISPAK_2196`).

## Что не покрыто

`CClose`/`zaver`, `CRemove`, `CFindLast`, `CFindEnd`, `CInclude/CExclude/CReinclude`, `CFindOwner`, `CGetKnotByKey`, `WPASRA`/`VPASR6`, `SSREZK`, `TPCMPNNA`, `TCMPIN`/`TCMPINP`, транслятор ЯОД/ЯМД и модель данных КОМПАС.

Создание области и три начальные записи сделаны прямыми вызовами МАРС (`PASACD`/`PASSETAR`/`NEWD`/`OPEND`/`PUTD`), потому что у `COMTUP` нет входа `NEWD`.

## Оценка

Это **интеграционный тест порта COMTUP на БЭСМ-6 с семантикой уровня СУБД**, а не тест КОМПАС в сильном смысле: не запускаются `UCOMPAS.PAS`, `TSSDML`, транслятор ЯОД/ЯМД, схемы и типы. PIC логируется, а не интерпретируется; слоты `BDVECT` задаются вызывающим кодом по жёсткому соглашению. Как регрессионный тест для `src/comtup.pas` пригоден.

Из наблюдений: `CReplace` через `7439` требует `BDVECT[13].i = 41₈`; при `4` МАРС выдаёт `06 DАТА ВАSЕ ЕRRОR`, при `144₈` программа падает. Значение `41₈` подобрано по дампу `MODD` и подтверждено только на этой конфигурации. `PIC NC=0, NA=16` означает, что часть счётчиков затирается при `PASBD` либо `APIC` возвращает другую копию структуры; по этим полям семантику проверять нельзя.
