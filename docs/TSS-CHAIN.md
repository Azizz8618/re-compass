Языковые находки, подтверждённые отдельными пробами в `tests/`:

1. `[^ ]` Фигурные скобки не являются комментариями: проба `tests/brace.pas`
   даёт `******84` и символ `≡` в листинге.
2. Строки деки обрезаются до 72 символов. Строка прелюда длиной 74 символа

   финального исходника укладываются в 72 байта.
3. Идентификатор не может содержать подчёркивание: `Compile_Method`,
   `Print_Methods`, `Map_Method` переименованы в `CompileMethod`,
   `PrintMethods`, `MapMethod`.
4. `Addr(x)` отсутствует как стандартная функция 15.1 (пробы

6. Объявления `const/type/var` обязаны предшествовать первому `procedure`.
7. Типизированные константы 15.1 не поддерживаются, поэтому реальный
   `SLANGM` из `TSLM.PAS` придётся инициализировать операторами, а не

## 4. Что именно блокирует настоящий запуск (факт + гипотеза)

Факт: v11 компилируется, но не связывается. Прогон с `*execute`
(`logs/tsspr-v11-run.run`) печатает `ОТСУТСТВУЕТ` для 14 внешних входов:
`TPCMPP1`, `TPCMPIN1`, `WPASRA`, `EXN`, `TPCMP1I`, `VPASR6`, `TPCMPL1`,

`APIC2`. То есть синтаксическая доступность цепочки доказана, исполнимая
цепочка ещё не собрана.

Факт: в scratch-копиях 2348 и 2196 нет библиотеки с `COMTUP`/`UCOMPAS`;
`src/comtup.pas` из репозитория существует и в прошлых сессиях собирался в
зоне 2570 с 18 входами, но в текущий scratch он не записан. Это обратимо:
достаточно отдельной декой собрать `comtup` в свободную зону и подключить её
через `*perso`, не трогая PASCOMPL.

Факт: большинство процедур в v11 являются заглушками: `DML`, `INKOMP`,
`INBPEM`, `zamtrb`, `SSENDM`, `ERM`, `howcom`, `VarLength`, файловые
процедуры. `SLANGM` не заполнен. Три присваивания адресов заменены на `nil`.
Поэтому v11 не является рабочим портом `TSSPPR`.

Гипотеза (вытекает из Sized/структур): даже после подключения `COMTUP`
потребуется семантическая согласовательная работа. `PicT` из
`src/predtgen.pas` (поля `nc,nm,na,smes,ssdmo,m[0..383],l[0..383]`) не
совпадает с `TYPPIC` из `TSPIC.PAS` (есть `ipcx`, `x`, `l` с пятью вариантами,
`m` и др.). `UCOMPAS`/`TSSPPR` зашиты на числовые слоты БДВЕКТ PC-ядра, а
`src/comtup.pas` отображает их в МАРС-6 не для всех 296 вызовов `TPCMPP1` в
`TSSPPR`. Без поразрядной сверки с листингом `TSSPPR.PRT` корректность
полученного object code не гарантирована.

Гипотеза: главный несинтаксический блокер - `TSSERR` (GUI-зависимости
`Op*`). Практический обход - оставить интерфейс `ERROUT(A,B3,NEJT)` и
`howcom(NM)`, но реализовать их через `WRITELN` в `OUTPUT` и `*BDERRN*`, как
это уже сделано в ported `src/servis.pas`. Аналогично `TSSDMPR` нужно
переписать на прямые `WRITE/WRITELN` Монитора, сохранив сигнатуры
`PUTALF/PUTEOL/PUTINT/PUTPOL`.

Оценка трудоёмкости (гипотеза, по опыту порта `TSERVIS` и механического
перевода `TSSPPR`): `TSSBAS`+`TSPIC`+`TSLM`+`TSSZT` - 0,5-1 день;
`TSSDMPR`+`TSSERR` (без GUI) - 1-2 дня; `TSSDML` (3142 строки) - 3-5 дней;
семантическая доводка `TSSPPR`/`OPBIB` и сверка с `.PRT` - 1-2 дня;
front-end для `&&...&&` - 2-4 дня. Итого 7-14 дней агентского времени, то
есть оценка плана «4-7 дней» оптимистична.

## 5. Точный план запуска 18 программ

### 5.1 Front-end (факт по тексту дек + гипотеза по реализации)

В деке 12-14 находится 345 пар `&&...&&`. Это встроенный язык манипулирования
данными (ЯМД) внутри Pascal: `HAЙTИ ПEPBYЮ`, `HAЙTИ CЛEДYЮ`,
`HAЙTИ ПO-KЛЮ`, `BЗЯTЬ`, `ЗAMEHИ`, `ПOCTABИTЬ`, `YБPATЬ`, `BKЛЮЧИ`,
`ИCKЛЮЧ`, `ECЛИ COCT`, `ЖYPHAЛ`, `KOMПAC`, `ЗABEPШ`. Паскаль-Монитор не может
их разобрать как Pascal, поэтому нужен препроцессор:

1. Извлечь текст каждой `PROGRAM` по absolute line ranges из section 5.2.
2. Заменить каждую пару `&& S &&` на вызов `DMLCALL(<номер сниппета>)`, где
   `DMLCALL` кладёт строку в `BUF.M`, выставляет `BUF.I/BUF.D/BUF.H` и
   вызывает настоящий `DML(TRUE)` из ported `TSSDML`.
3. Оставить остальной Pascal без изменений, включая `(*=L0 ... *)` и
   директивы `(*=...*)`; перевести `{` в `(*` и убрать подчёркивания в
   идентификаторах только если они встречаются в исходниках дек.
4. Компилировать каждую программу отдельной декой с `*perso:402570` плюс
   библиотеки `COMTUP`, `SERVIS`, `UCOMPAS`, `TSSDML`, `TSSPPR`.
5. Перенести печать меню и отчётов на `WRITELN` Монитора; ожидаемые строки
   берутся из тех же дек (это эталон, а не новый текст).

`src/predtgen.pas` пригоден только как генератор микрокоманд МАРС для отдельного
оператора, не как парсер ЯМД. `src/servis.pas` уже работает как порт
`TSERVIS.PAS` и должен использоваться для операций с областями, а не
переписываться заново.

## 7. Вывод

Факт: инлайнирование типов и восстановление сигнатуры `OPBIB` позволило
свести число синтаксических диагностик с 162 до нуля на Паскаль-Мониторе 15.1.
Это доказывает, что механический порт цепочки TSS 가능, но не доказывает его

только после трёх пилотов и проверки критериев из section 5.2.
