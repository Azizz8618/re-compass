# Области данных КОМПАС (.ARE)

`.ARE` - не архивы, а файлы областей базы данных КОМПАС. 510 файлов в архиве Ильина, 55 имён, 156 уникальных содержимых, суммарно 5 419 023 байт. Даты 1989-02-01 - 1995-12-17. Полная инвентаризация: `/tmp/.private/azizz/opencode/are-inventory/` (scratch).

## Формат страницы

Страница = 2048 байт = 1024 16-разрядных слова little-endian. Размер файла всегда кратен 2048 (кроме 15 однобайтовых заглушек и 173 нулевых файлов).

| Поле | Смещение | Значение |
|---|---|---|
| `w[0]` | 0 | идентификатор области (ADA=1, SC=2, BPEMEH=3, ZPROC=4, EXPERT=8) |
| `w[1]` | 2 | номер страницы |
| `w[2]` | 4 | конец таблицы дескрипторов (в словах) |
| `w[3]` | 6 | адрес первой записи в зоне данных (в байтах) |

Дескриптор - 4 слова (8 байт): локальный номер, номер knot-типа, длина, адрес. Адрес и длина - **байтовые** смещения внутри страницы; зона данных растёт с конца страницы назад. Для `ZPROC.ARE` интервалы `[addr, addr+length)` точно заполняют диапазон 1705..2047.

Схема хранится в тех же файлах: записи `TYP`, `IT`, `RC`, `ST`, `CX`, `SYSTEM`. Нумерация knot-ов совпадает с `NewKnot(...,N)` из `GSC.PAS`: `AREA=2`, `IT=6`, `PROCS=9`, `RC=11`, `ST=14`, `SUBCX=15`, `SYSTEM=17`, `TYP=19`. Символы CP866 лежат по два в 16-разрядном слове.

`LENOP=384`, `LENLIT=383`, `TYPPIC` из `TSPIC.PAS`/`MICROCOD.TXT` описывают оперативную карточку процесса PIC, а не формат `.ARE`; переносить нужно формат области, а не `TYPPIC`.

## Декодер

`tools/are_decode.py <файлы.ARE> [--out sample.json] [--limit N]` читает страницы и дескрипторы, декодирует текст CP866, помечает дескрипторы вышедшие за страницу флагом `invalid`.

Проверка на контрольных файлах (`pascal-sources/01_SYS_ARJ/`):

| Файл | Размер | Страниц | ID области | Дескрипторов на стр. 0 |
|---|---:|---:|---:|---:|
| `ZPROC.ARE` | 2048 | 1 | 4 | 15 |
| `ADA.ARE` | 28672 | 14 | 1 | 37 |

## Контрольные наборы

- Минимальный системный: `ADA + BPEMEH + OBPEM + SC + ZPROC` (13 каталогов).
- Кадровый: `A1/A2/C1/C2 + KOHTP`.
- Библиотечный: `ADA/BIB/BPEMEH/CBIB/DOCER/MAG/OBPEM/SC/ZPROC`.
- Полный 28-областный: `AENUM`, `AFIGUR`..`ZFIGUR`, `XAFIG`..`XDFIG`, `SENUME`.
- Пользовательские данные: `BENAR.ARE` (справочник организаций, 79872 байт, 1995-12-17), `DBASA.ARE` (химическая БД), `KOHTP.ARE` (кадровый пример), `PRIM.ARE` (1989-02-01).

Две копии `DOCER.ARE` из `FIL.ARJ~/KOOP/` имеют ошибки CRC и не годятся как эталоны.

## Как PC работает с .ARE

`K61.TXT` перечисляет состав `areas.zip`: `ADA.ARE` - административная БД, `ZPROC.ARE` - административная, `MAG.ARE` - для MAD, `OBPEM.ARE` - временный набор, `DOCER.ARE` - сообщения об ошибках. Компас ищет файлы в каталоге из переменной `COMPASS`.

`TSERVIS.PAS` - единственный модуль, отображающий область на DOS-файл: `FILAR, FILAR2: FILE OF TYPLI`, `TYPLI = ARRAY[0..1023] OF INTEGER`. `SETFL` строит имя `COMPASS + TrimTrail(ss^.area.anm) + '.are'`; `SSobm` делает `SEEK`/`read`/`write` страницы. Остальные модули (`TSSBAS`, `COMTUP`) файлами не управляют.

## Что это даёт для БЭСМ

Прямой побайтовый перенос невозможен: PC-слово 16 бит с CP866 (2 символа), слово БЭСМ-6 - 48 бит с 6-битным алфавитом (6 символов). Нужна транскодировка: символьные поля объединяются по три PC-слова в одно слово БЭСМ, числовые расширяются, дескрипторы пересчитываются. МАРС ожидает 6-символьный ключ в одном слове.

Практический путь (принят к выполнению):

1. Python-декодер (готов) даёт JSON со списком ключей и значений.
2. Генератор деки Pascal-Монитора: `PASACD`/`PASSETAR` (идемпотентно по `BDVECT[36]`), `NEWD`, `OPEND`, затем `PUTD` для каждого ключа.
3. Проверка: `FIND` -> `GETD` -> сравнение с JSON, `EXN = 0`, `ITLEN` равна ожидаемой длине, повторный прогон даёт байтово идентичный вывод.
4. Начинать с одностраничных `ZPROC.ARE`/`MAG.ARE`, затем `ADA.ARE`.

Импорт `.ARE` заменяет `*CMP` как источник эталонных данных, но не как инструмент разработки новых схем: `.ARE` - статический результат трансляции конкретной схемы.
