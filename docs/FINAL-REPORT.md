# Промежуточный отчёт

Состояние на 23.11.2026. Отчёт обновляется по мере появления проверяемых артефактов.

## Главный вывод

Основной текст КОМПАС сохранился на Pascal (PC-ветка Turbo Pascal 5/7 из архива Ильина). Нижний уровень работы с носителями в PC-версии - `COMTUP.PAS` и `COMPASST.OBJ` - подлежит замене на вызовы системы МАРС, которая доступна на БЭСМ-6 и вызывается из Pascal. Рабочий диск - 2348. Задача сводится к порту нижнего уровня, а не к написанию системы с нуля.

## Что сделано

- Клонирован пустой репозиторий `re-compass`, создана структура проекта, сделан начальный коммит.
- Инвентаризирован архив Ильина: 804 файла, 207 каталогов. Вложенные архивы вскрыты рекурсивно.
- Найдены и прочитаны Pascal-исходники: `TSSDML.PAS` (3142 строки), `COMFY.PAS`, `TTC.PAS`, `UCOMPIL.PAS`, `UCOMPAS.PAS`, `CMPSNO.PAS`, `TSPIC.PAS`, `COMTUP.PAS`. Составлен список «брать как есть / портировать / заменять»: `PASCAL-SOURCES.md`.
- Подтверждено прямое указание на ДИСПАК/ДИАПАК и требования 240/63 восьм. зон (`K1T1.TXT`).
- Подтверждено наличие ядра БАНДИТ на диске 2348 в зоне 0657 и интерфейсных модулей `PASBDI`/`PASACD` в зонах 1700/1712/2000/2007. Контрольная сумма дампа зоны 0657 одинакова для обеих копий образа.
- Собраны правила работы с 2348 из смежных проектов: `RULES-2348.md`.
- Проведён дымовой тест МАРС из Pascal: дек `tests/mars_smoke.b6`, эталон `tests/mars_smoke.expected.txt`, два прогона байтово идентичны. Баннер 15.1, ошибок МАРС нет.
- Декодированы числовые константы `UCOMPAS`: это слова микропрограммы PIC (`W(low,high)`), а не коды МАРС. См. `PIC-MICROCODE.md`.
- Составлена таблица соответствия 17 процедур `COMTUP` операциям МАРС: `COMTUP-MAPPING.md`. 15 из 17 работают с внутренним состоянием PIC/TSR и требуют `PASBDI`/`PASBD`.
- Подготовлен рецепт внешних процедур по образцу `arfalib`: `EXTERNAL-PROCEDURES.md`. Вся МАРС-обвязка уже есть в библиотеке зоны 2570.
- Экспериментально доказана передача адреса через `BDVECT[k].P := REF(P)` и запись МАРС в переменную вызывающего (`BDVECT-ADDRESS.md`); нетипизированный `VAR P` невозможен, нужны типизированные обёртки.
- Проверена сборка модуля с 17 точками входа на эмуляторе: все имена разрешились, `ДЛИНА LIBRARY 031 ЗОН`, предел 19 входов (`BUILD-VERIFICATION.md`).
- Сохранены проверенная оснастка (`src/comtup.stub.pas`, `tests/comtup_build.b6`, `tests/comtup_test.b6`) и помеченный как некомпилированный черновик `src/comtup.draft.pas`.
- Реализован и скомпилирован рабочий модуль `src/comtup.pas`: 18 входов, все extern разрешены, COMMON-состояние и `*BDERRN*` работают (`COMTUP-IMPLEMENTATION.md`).
- Подготовлены критерии интеграционного теста `CGetBdKey` (`CGETBDKEY-TEST.md`).
- Интеграционный тест проведён: создана фикстура `kbd001` с бд-ключом `6000₈ = 3072`, выявлен и исправлен дефект `PicCode` (op 4), реализован op 90 через микрокоманду МАРС op53. `R = 3072`, `BDERRN = 0`. Модуль пересобран: 18 входов, `ДЛИНА LIBRARY 032 ЗОН`.
- Подготовлен список правок верхних слоёв `UCOMPAS`/`TSSPPR` для новых оберток с номером слота (`CALLER-PATCHES.md`).
- Подтверждено, что 2348 содержит тот же код МАРС в зоне `630₈`, что и 2048. Однодисковая схема `лен 40(2348-630)^` + `лен 41(2348)^` работает.
- Исправлен неидемпотентный `SSBF5`: холодная инициализация только при `BDVECT[36] = 0`. Внешний `COMTUP` с фикстурой в том же процессе даёт `R = 3072`, `BDERRN = 0`, `EXN = 0`. Модуль пересобран: 18 входов, `ДЛИНА LIBRARY 032 ЗОН`.
- Реализован op 89 (запись бд-ключа) инвертированной op53 `243553c`: `S29=10000₈`, `R=4096`, `BDERRN=0`. Оговорка: изменение не сохраняется на диске.
- Разобран байтовый поток PIC (`PIC-BYTE-STREAM.md`): старший байт - отдельная операция либо параметр предыдущей; `512=(0,2)` - не op2, а `ADRF=2`.
- Подготовлены минимальные патчи верхних слоёв в `patches/` (24/1/30 изменённых строк, dry-run пройден).

## Что не найдено

- Готовой КОБЛЫ на образах дисков: она создаётся во время прогона.
