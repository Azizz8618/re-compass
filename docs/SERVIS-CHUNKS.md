## 1. Формат реестра (факт)

Ключи МАРС ровно 6 символов; записи `PUTD`/`GETD` одnosловные:

| Ключ | Смысл | Значение в опыте |
|---|---|---|
| `RGLEN ` | полная логическая длина | 1750 |
| `RGNCHK` | число кусков | 2 |
| `RC1KB ` | TAR куска 1 (`LU<<12\|зона КОБЛЫ`) | 137280₈ = `0414100` |
| `RC1ZN ` | базовая зона области | `4201₈` |
| `RC1LN ` | длина куска | 1000 |
| `RC1OF ` | смещение | 0 |
| `RC1NM ` | имя области (alfa в слове) | `REGIST` |
| `RC2KB `…`RC2NM ` | то же для куска 2 | `0416000`, `6101₈`, 750, 1000, `SCL2  ` |
| `C1LEN `, `C1OFF `, `C1D0  `…`C1D2  ` | данные куска 1 | 1000, 0, 101/102/103 |
| `C2LEN `, `C2OFF `, `C2D0  `…`C2D2  ` | данные куска 2 | 750, 1000, 201/202/203 |

Итого 17 ключей в одной области МАРС `REGIST`. Реестр хранится на дисковом
паке LU `41₈` с монтированием `-wr`; на барабане LU `27₈` состояние между
задачами, как показано в `chunk-registry/report.md`, не сохраняется.

## 5. Ограничения, опровергнутые гипотезы и гипотезы

- **Факт:** `PASACD` можно вызывать только один раз на процесс. Попыткаwriter 1
  создать сначала КОБЛУ реестра, а затем КОБЛУ куска, приводила к тому, что
  свежий процесс не открывал `REGIST` (ошибка 05). Это соответствует
  `docs/MARS-INTERFACE.md`: повторный `PASACD` затирает описатель первой КОБЛЫ.
  Поэтому реестр и данные куска 1 теперь живут в одной области `REGIST`,
  а writer 2 создаёт только свою КОБЛУ.
- **Факт:** область на 1000 зон вмещает только 14 ключей: 15-й `PUTD`
  завершался `06 DАТА ВАSЕ ЕRRОR`. Область на 14 зон приняла все 17 ключей
  (как в эталонном `reg_w.b6`). Гипотеза: ёмкость корневой страницы каталога
  зависит от длины области; прямого дампа каталога не снималось.
- **Опровергнутая гипотеза:** «alfa-ключи, возвращаемые функцией, непригодны
  для `PUTD`». После замены динамических ключей на литералы ошибка осталась
  на том же 15-м `PUTD`; настоящая причина - ёмность каталога.
- **Опровернутая гипотеза:** «ранний `pasbdi` портит последующий `PASSETAR`».
  Удаление `ClrErr` из урезанного `Init` не убрало ошибок 05/02.
- **Факт:** info word, TAR и ключи SERVIS-версии побайтно совпадают с
  проверенными константами (`20414100c`, `1750414201c`, `414100c` и т.д.),
  что исключает ошибку адресации как причину ранних отказов.
- **Гипотеза:** физический размер области `REGIST` (14 зон) меньше логической
  длины куска 1 (1000), но это и есть назначение обходного пути: 1750 зон
  существуют только в дескрипторе SERVIS и в реестре, а не в ядре МАРС.
- **Гипотеза:** для большего числа кусков понадобится либо несколько
  14-зонных областей реестра в разных КОБЛАХ (по одной на задачу), либо
  уплотнение дескрипторов; текущая схема ограничена 17 ключами на область.
