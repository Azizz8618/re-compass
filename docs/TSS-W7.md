1. **Меню-ветви.** Прогенерено 31 decks в `decks/final/`. Для ZATMON - отдельные
   деки на каждый пункт меню (`PEГ`+`KOФ/OTД/TEM/ФAK/OБЩ/KOH/BЫX`,
   `OTЧ`+`ПOC/KOH/BЫX`, `CИC`+`KOH/BЫX/ФЛA`, главное меню `ЗAK/CБP/ПAP/BЫX`).
   Обнаружена особенность ввода: `READ(input,ПAPCИC)` для пароля оставляет
   указатель внутри карточки, поэтому для ветвей `03/02` и `03/03` ключ должен
   стоять в той же карте сразу после шести символов пароля:
   `TECT  BЫX   ` и `TECT  ФЛA   `. Для ZATZAT/ZATNAK/ZATRTE добавлены деки с
   ключами `HOB`, `ИCK`, `BЫX`, `ЭTA`, `ПPO`.
2. **Полевые ветви.** Тестовый драйвер W6c расширен: каждая процедура
   (`ПOCTAB`, `BЗЯTЬ`, `HAЙTИ`, `HOB`) вызывается со всеми значениями
   `BOSX.NAM`/`NAM` из `docs/severov-apps/W6C-INVENTORY.json` (43+7+11 вызовов).
   Для `HOB` дополнительно выставляются `CULX.CUPX.NAM` и `ЦX:=1`, чтобы во
   втором проходе внутреннего цикла достигались ветви SELECT 4 с условиями
   `MEC<>0`, `TEM<>0`, `OTД<>-1`.
3. **Ограничение циклов тестового драйвера.** Ветви с `NEXT:=FALSE` зацикливали
   внутренний `REPEAT`, потому что курсорная заглушка `NEXTPAR` становится
   `TRUE` только после второго вызова. Введена функция `W6GUARD` (счётчик до 4),
   подставленная в `UNTIL NEXT` только в scratch-портах. Это не меняет условий
   SELECT и не добавляет DMLCALL; помечено в исходнике как `W7-GUARD`.
4. **Схема MAD.** В четыре порта введены объявления наборов с префиксами из
   настоящих дек `tests/deck08.b6` и `tests/deck09.b6` (`SY-TEM=AC`,
   `TE-ИCП=B1`, `OT-ИCП=B2`, `ИC-ИCП=B3`, `SY-ПAP=PA` и др.). Раньше `Qns=0`,
   поэтому `FIND FIRST` печатал пустое имя набора. Теперь в логах фигурируют
   настоящие имена наборов.

## 3. Почему `MAD FULL ЕХ=4` не устранён: доказательства и stopping point

Это вторая Residual-причина задания. Она **не устранена**, и я не выдаю её
устранением. Ниже конкретные ошибки.

1. В `QLoadRec` портов вызывается `getd(Qck,Qv8)`. Инструментированная копия
   (`work/ZATZAT-dbg.pas`, лог `logs/dbg-ZATZAT2.run`) показала вызов
   `GЕТD-DBG КЕУ=[] ВNО=1 SS=1 QNS=0`: ключ пустой. МАРС отвечает
   `01506В АDR, 04 DАТА ВАSЕ ЕRRОR, 221411 МIСRО RUN, NАМЕ=`, `ЕХ=4`.
2. Пустой ключ получается не из отсутствия одних только данных. Интерпретатор
   МАД в стеке реализует `НАЙТИ ПО-КЛЮЧУ ... B <набор>` как операцию "владелец"
   (код `z=6`) и берёт ключ из 8-го слова буфера `Qbf`, а не из значения поля,
   указанного в сниппете. Для сниппета 274 (`НАЙТИ ПO-KЛЮ Ц! B SY-TEM`) разбор
   даёт `Qx1='ПO-KЛ'`, `QFindSet=0`, буфер пуст. То есть семантика `ПО-КЛЮЧУ`
   в реконструкции не реализована. Это подтверждено тем, что после введения
   настоящих объявлений наборов (`Qns=8`, `SЕТS=8`) ключ остаётся пустым.
3. При принудительной подстановке корректного ключа (`AC0001`) в логе
   `logs/keyfix2-ZATZAT.run` ошибка меняется на
   `03 DАТА ВАSЕ ЕRRОR ... NАМЕ= АС0001`, то есть записи просто нет. Значит
   механика `getd` рабочая, но area, в которую грузятся данные, приложением
   не открыта: `BDVECT[36]=0` в точке входа в главный блок (лог
   `logs/bd36-ZATZAT.run`).
4. Попытка открыть area из приложения не даёт результата: `PASSETAR(270000c)`
   + `OPEND('ZGEN  ')` даёт `05 DАТА ВАSЕ ЕRRОR ... NАМЕ= ZGЕN`
   (`logs/boot5-ZATZAT.run`), а с `PASACD(20270000c)` - `10 ... NАМЕ= ZGЕN`
   (`logs/boot4-ZATZAT.run`): повторная холодная инициализация КОБЛЫ затирает
   каталог area. Загрузка `tests/deck09.b6` сама по себе проходит с
   `MAD ЕХ=0` и данные сохраняются между заданиями (повторный прогон даёт
   `FIND FIRSТ SУ-ТЕМ N=3`), но приложение их не видит.

Итог по пункту 2 задания: `EX=0 во всех прогонах` недостижим без реализации
`ПО-КЛЮЧУ` и без подключения пользовательских area МАД к интерпретатору.
Приглушить ошибку в `QLoadRec` (счесть пустой ключ "запись не найдена") я
сознательно не стал: это было бы сокрытием дефекта, а не работой с данными.
Фактическое состояние: в финальных логах `EX4` есть только у трёх
полевых драйверов (ZATZAT 273, ZATNAK 60, ZATRTE 112); ZATMON и ZATTAB
дают только `EX0/EX3/EX8` и `EX0` соответственно.

## 4. Какие данные КОМПАС нужны и что реально загружено

По тексту сниппетов (`docs/severov-apps/snippet-map.json`) и gold-тексту
наборы, к которым обращаются приложения:

| Программа | Наборы (из текста MAD) |
|---|---|

| ZATZAT | `SY-TEM`, `TE-ИCП`, `TE-ЭTA`, `OT-ИCП`, `ИC-ИCП`, `ИC-ЗAT`, `ЭT-ЗAT` |
| ZATNAK | `SY-HAK`, `HAKЛ` |

Префиксы ключей (`AC/B1/B2/B3`, `63/66/74/76/77/78`) и формат карт `SET`/

По требованиям задания построена дека загрузки **настоящих** данных ARE:
`data/ADA-real-load.b6` сгенерирована проверенным генератором
`are_to_mars_multi.py` из `ADA.ARE` (area_id=1, 14 страниц, 379 валидных
дескрипторов), загружает 40 ключей `ADpnnn` в area `ADATA`, info word

`FINAL ЕХN=0`, `stderr=0`; ключи перечислены в `data/ADA-real-keys.json`.
Однако эти записи - дескрипторы ADA, а не пользовательские записи MAD
(`SY-*`, `TE-*`, `ПA-*`), и приложения их не читают по причинам раздела 3.
В архиве Ильина пользовательские MAD-данные в пригодном для БЭСМ виде
отсутствуют: `MAG.ARE` из `KOMPAS2/AREAS.ZIP` - это PC-формат (2048 байт,
area_id=5, 4 дескриптора), а сниппеты содержат только текст операций.
Поэтому реальные записи для `SY-TEM/ПA-ДEЙ/...` загрузить нечем. Это второй
stopping point.

## 5. ZATTAB

Полная логика (15 процедур, 19 сниппетов) сохранена. В scratch-копии
`src/ZATTAB-final.pas` добавлены только настоящие объявления наборов MAD
(п. 4), то есть синтетическая часть **минимизирована до значений**: схема и
последовательность операций берутся из gold, а не выдумываются. Прогон
`final-ZATTAB-final`: `exit=0`, `stderr=0`, 224 строки `МАD FULL ЕХ=0`,
`ТАБЛИЦА ЗАТРАТ ЗА МЕСЯЦ` и строка `ИТОГО` на месте, `КОНЕЦ ЗАДАЧИ`.

Полная замена `APPLYMAD` на реальные таблицы невозможна по тем же причинам:
`APPLYMAD` (строки 610-670 `src/generated/ZATTAB.pas`) возвращает константы
вида `ЗAT.BЫП:=100.0+ZTI*10`, `HAКЛ.ЗAPП:=1000.0` и массивы `THID/ISPOT/
ISPDI/ISPEP/ZATME`. В gold сниппеты 327-345 содержат только MAD-команды
(`НАЙТИ ПEPBYЮ B ПA-ДEЙ`, `BЗЯTЬ ПAP`, `HAЙTИ ПO-KЛЮ 'ИM-KOЭ' B SY-ПAP` и т.д.),
но не сами записи. Исходные данные 1988-1989 гг. (`SY-ПAP`, `ПA-ДEЙ`,
`SY-HAK`, `SY-TEM`, `TE-ИCП`, `ИC-ЗAT`, `ЭT-ЗAT`, `OT-ИCП`) в доступных area
отсутствуют. Числа в таблице остаются синтетическими; это явно зафиксировано
и не выдаётся за исторические значения.

## 7. Stopping points

1. Для полного `EX=0` нужна реализация семантики `НАЙТИ ПО-КЛЮЧУ <поле> B
   <набор>` в интерпретаторе МАД и открытие пользовательской area МАД в

2. Для замены синтетических данных ZATTAB и полевых драйверов нужны исходные
   записи area `SY-*`, `ПA-*`, `TE-*`, `ИC-*`, `ЭT-*`, `OT-*` в БЭСМ-представлении.
   В доступном архиве их нет; `ADA.ARE` загружена, но содержит другие записи.
3. Ветви с `NEXT:=FALSE` покрыты только благодаря таймеру `W6GUARD` в
   тестовом драйвере; это свойство окружения, а не исправление gold-логики.
